# visualthink

내용을 손그림 비주얼씽킹 다이어그램으로 그린다. **JSON만 작성하면 좌표·크기·줄바꿈은
라이브러리가 전부 계산한다.** 위치를 직접 지정할 수 없고, 지정할 필요도 없다.

## 워크플로

0. **만들기 전에 용도와 테마를 확인한다. 분량은 내용에서 정한다.**

   시각 산출물은 다 만든 뒤에 "다른 톤이었으면" 하는 일이 잦다. 스펙은 그대로
   두고 출력만 바꾸면 되므로, 용도와 테마는 먼저 정하고 시작한다.

   **사용자가 이미 말했다면 묻지 않는다.** "발표자료로", "보고서용", "손그림으로"
   같은 단서가 있으면 그대로 따르고 바로 만든다. 단서가 없을 때만 `AskUserQuestion`
   으로 **한 번에 두 질문**을 묻는다.

   | 질문 | 선택지 |
   |---|---|
   | 어디에 쓸 건가요? | **문서**(스크롤 한 장 HTML) · **발표**(카메라 프레젠테이션) · **임베드**(SVG를 다른 문서에) |
   | 어떤 톤으로? | **sketch**(손그림) · **flat**(깔끔한 벡터) · **editorial**(명조 에디토리얼) · **bold**(볼드 포스터) |

   용도에 따라 어울리는 테마가 다르니, 질문의 추천 표시를 이렇게 맞춘다.

   | 용도 | 추천 테마 | 이유 |
   |---|---|---|
   | 학습·아이디어 정리·설명 | `sketch` | 손그림이 "생각 중인 것"으로 읽혀 부담이 없다 |
   | 보고서·공식 문서 | `flat` 또는 `editorial` | 손그림이 가벼워 보이면 안 되는 자리 |
   | 발표·강연 | `bold` 또는 `sketch` | 멀리서 읽히는 크기 대비 |
   | 긴 글 요약·에세이 | `editorial` | 활자로 위계를 만드는 톤 |

   출력은 용도에 따라 갈린다 — 문서는 `VT.toHTML`, 발표는 `VT.toPresentation`,
   임베드는 `VT.render`. **셋 다 같은 스펙을 받는다.** 나중에 용도·테마가 바뀌어도
   스펙을 다시 쓰지 말고 호출만 바꾼다.

   **분량은 묻지 않고, 내용이 정하게 둔다.** 사용자가 아는 것은 "이걸 그림으로
   보고 싶다"까지고, 얼마나 필요한지는 내용을 읽은 쪽이 안다. 원본 전체를 훑어
   **살아남아야 할 논점을 빠짐없이 세운 다음**, 그 결과에 맞는 값을 고른다.
   목표 개수를 먼저 정해놓고 거기에 내용을 맞추지 않는다 — 채우려고 논점을
   부풀리지도, 줄이려고 필요한 논점을 버리지도 않는다.

   | `density` | 이런 내용에 |
   |---|---|
   | `brief` | 한 가지 주장으로 수렴하는 내용. 슬랙·이슈에 붙일 것 |
   | `standard` | 한 주제를 한 장으로 |
   | `detailed` | 여러 절이 있는 주제, 브리핑 자료 |

   한 장에 담기 벅찰 만큼 내용이 많아도 논점을 쳐내지 않는다. **층위를 올리거나
   (형제 논점을 상위 논점으로 묶는다) 장을 나눈다.** 사용자가 "간결하게",
   "자세히"처럼 분량을 직접 말했다면 그 말을 따른다.

   정한 값은 스펙에 적는다 — `{ "density": "brief" | "standard" | "detailed" }`.
   `validate()`가 이 값에 맞춰 블록 수와 라벨 길이를 검사해 경고를 낸다.
   블록 수 경고는 상한이 아니라 신호다 — 내용이 정말 그만큼이면 그대로 두고,
   한 장에 몰아넣을지 나눌지만 다시 본다. 길이 경고는 따른다.
   **경고가 나오면 캔버스를 키우지 말고 글자를 줄인다.** 넘치는 텍스트는
   깨지지 않고 작아지는데, 작아진 글자는 아무도 읽지 않는다.

1. **필요한 레퍼런스만 읽는다.** 기억에 의존해 JSON을 쓰지 않는다. 네 개로 나뉘어
   있으니 통째로 읽지 말고 그 판단에 필요한 것만 연다.

   | 파일 | 언제 |
   |---|---|
   | `references/composition.md` | 어떤 블록에 담을지, 한 장에 얼마나 담을지, 흔한 실수 |
   | `references/blocks.md` | 각 블록의 필드와 JSON, 아이콘, 도형 |
   | `references/theming.md` | 테마 4종의 생김새, 장식을 쓸 자리 |
   | `references/api.md` | `validate`/`render`/`toHTML`/`toPresentation`, 스펙 옵션 |

   보통은 `composition.md`로 구조를 정하고 `blocks.md`로 스펙을 쓰면 끝난다.

2. **빈 화면에서 시작하지 않는다.** `assets/specs/`에 완성된 스펙 네 개가 있다 —
   `starter-explain`(설명·학습), `starter-decide`(비교·결정), `starter-status`
   (현황 브리핑), `starter-brief`(짧은 한 논점). 가까운 것을 열어 내용을 갈아끼우는
   편이 처음부터 쓰는 것보다 빠르고 덜 틀린다.

   **블록은 내용의 *모양*에 맞춘다.** 텍스트의 모양이 아니다.
   순서가 있으면 `flow`/`steps`, 대립하면 `compare`, 한 개념의 갈래면 `mindmap`,
   두 축으로 평가하면 `matrix`, 계층이면 `pyramid`.
   전부 `list`로 만드는 것이 가장 흔한 실패다.

3. **스펙을 쓰고 반드시 검증한다.**

`<skill>`은 이 SKILL.md가 있는 폴더의 절대경로다. 의존성은 없고 번들 한 개가 전부라
설치할 것이 없다.

```js
const VT = require('<skill>/assets/visualthink.js');
const check = VT.validate(spec);
if (!check.ok) { /* check.errors 를 보고 스펙을 고친다 */ }
if (check.warnings.length) console.warn(check.warnings);   // 아이콘/색 오타

// 0단계에서 정한 용도에 맞는 출력만 고른다
fs.writeFileSync('out.html',  VT.toHTML(spec, { theme }));         // 문서
fs.writeFileSync('deck.html', VT.toPresentation(spec, { theme })); // 발표
const svg = VT.render(spec, { theme });                            // 임베드
```

4. **결과를 눈으로 확인한다.** 시각 산출물이라 렌더 성공만으로는 부족하다.
   agent-browser 스킬로 열어 스크린샷을 찍고 겹침·잘림·빈 공간을 점검한 뒤
   전달한다. agent-browser를 쓸 수 없으면 확인하지 못했다고 말하고 넘긴다 —
   안 본 것을 본 것처럼 넘기지 않는다.

## 기억할 것

- 카드 `text`는 20자, `note`는 40자 이내(`standard` 기준). 문단은 카드가 아니라
  `callout`에.
- `color`는 의미가 있을 때만 지정한다(빨강=위험, 초록=완료). 나머지는 자동 배정에 맡긴다.
- 블록 종류를 섞는다. 같은 블록 여섯 개는 다이어그램이 아니라 벽이다.
- **꾸밈은 드물어야 강조로 읽힌다.** `mark`는 한 장에 한두 개, 기울임은 낱장
  메모에만. 꾸밈은 `sketch` 테마의 것이고 `editorial`·`bold`에서는 오히려
  디자인을 해친다.
- 테마는 스펙을 바꾸지 않고 `theme`만 바꾼다. `editorial`·`bold`는 타이포 중심이라
  **라벨이 짧을수록 좋다** — 답답해 보이면 캔버스를 넓히지 말고 단어를 줄인다.
  네 테마의 생김새와 꾸밈 기준은 `references/theming.md`가 주인 문서다.

## 산출물

세 호출 모두 같은 스펙을 받는다. 옵션과 조작키는 `references/api.md`.

- `VT.toHTML(spec)` — 단일 HTML. 저장하면 바로 열린다
- `VT.toPresentation(spec)` — **발표를 요청받으면 이것.** 슬라이드가 아니라 한 장의
  캔버스를 유지한 채 카메라가 블록마다 확대·이동한다
- `VT.render(spec)` — SVG 문자열. explainer·webdoc·mograph 등 다른 HTML 산출물
  안에 그대로 넣을 수 있다
