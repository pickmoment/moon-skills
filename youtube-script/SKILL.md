# youtube-script — 시리즈형 유튜브 대본 집필

주제를 받아 **시리즈로 설계하고, 편별로 읽으면 바로 녹음되는 완전 축어 대본**을 쓴다.
산출물은 요약이나 개요가 아니라 **낭독 원고** — 토씨까지 확정된 문장만 들어간다.

이 스킬이 지키는 세 가지:

1. **깊이는 폭이 아니다.** "3가지 이유"를 나열하는 대본은 쓰지 않는다. 질문 하나를 표면 → 메커니즘 → 원인 → 파급까지 층으로 파고든다 (`references/craft.md` §3).
2. **몰입은 우연이 아니다.** 콜드 오픈, 열린 루프와 회수, 재후킹 지점, 문장 리듬은 설계 대상이다 (`references/craft.md`).
3. **사실은 근거를 갖는다.** 모든 수치·고유명사·인용은 제공 소스나 검색 결과에 대응되고, 대본 하단 `## 출처`에 매칭된다. 못 찾은 건 지어내지 않고 `## 미확인 사항`에 남긴다.

## 0. 진행 절차

### 1단계 — 입력 파악

사용자에게서 확보할 것 (없으면 물어보지 않고 기본값으로 진행하되 보고 시 알린다):

| 항목 | 기본값 |
|---|---|
| 주제 | 필수 — 없으면 물어본다 |
| 포맷 트랙 | 주제 성격으로 판단 (`references/formats.md` §0). 사건·역사·구조 해설 → 롱폼 내레이션 / 방법·의견·경험 → 토킹헤드 |
| 편당 길이 | 롱폼 내레이션 18분 / 토킹헤드 12분 |
| 시리즈 편수 | 주제 크기에 따라 3~6편 (`references/series.md` §2) |
| 소스 | 사용자가 직접 전달한 내용(문서·텍스트·링크·구두 설명)과 방향성 |
| 출력 모드 | 지정 없으면 **구조 대본**. 첫 편 집필 전 한 번 확인하고 이후 편은 같은 모드 유지 (§2) |
| 채널 톤 | 중립·정보형. 기존 시리즈 바이블이 있으면 그것을 따른다 |

**소스 범위** (`references/craft.md` §8):

1. **사용자가 직접 전달한 내용이 유일한 1차 소스다.** 문서·텍스트·링크·구두 설명을 전부 읽고, 거기 담긴 관점과 방향성(무엇을 말하려는 영상인가)을 먼저 확정한다.
2. **리서치는 최신 정보 확인으로만 한다.** 사용자가 잡아준 방향을 따라가는 데 필요한 현재 시점의 사실 — 수치, 날짜, 최근 상황, 고유명사 표기 — 을 `WebSearch`/`WebFetch`로 확인·갱신한다.
3. 그 외 자료를 스스로 찾아 넣지 않는다. 프로젝트에 쌓인 다른 노트나 관련 문서를 임의로 뒤져 근거로 삼지 않는다 — 사용자가 지정하지 않은 소스는 방향성을 흐린다.
4. 리서치가 사용자의 방향과 어긋나는 사실을 내놓으면, 대본에서 몰래 방향을 틀지 않고 **사용자에게 알린다.**

### 1.5단계 — 출력 모드 확인

대본 파일에 낭독 문장 외의 것을 넣을지 정한다. 첫 편을 쓰기 전에 **한 번만** 묻고, 시리즈 바이블에 기록해 이후 편은 같은 모드로 간다. 사용자가 이미 말했으면 묻지 않는다.

| 모드 | 파일 | 안에 들어가는 것 |
|---|---|---|
| **A. 구조 대본** (기본) | `{NN}-{슬러그}.md` | 메타(핵심 질문·반전·루프 장부) + 타임코드 헤딩 + 낭독 문장 + `## 출처` + `## 미확인 사항` |
| **B. 순수 대사** | `{NN}-{슬러그}.txt` | **읽을 문장만.** 헤딩·타임코드·메타·출처·주석 전부 없음. 마크다운 문법도 쓰지 않는다 |
| **C. 화면 대본** | `{NN}-{슬러그}.sv.md` | 낭독 문장을 **화면 한 컷 단위 문단**으로 쪼개고, 컷마다 장면 타입·이미지·메모를 붙인 것. `scriptviz` 스킬이 그대로 읽어 화면을 만든다 |

**C 는 A·B 를 대신하지 않는다 — 함께 낸다.** 대본의 질(문장 흐름)과 화면 설계는 다른
작업이라, A 로 대본을 완성한 뒤 그것을 컷으로 쪼개 C 를 파생시킨다. 순서를 뒤집으면
문장이 화면에 끌려다닌다. 영상 화면까지 만들 거면 A + C, 성우에게만 넘기면 B 다.
자세한 건 `references/templates.md` §5.

- 모드 B를 골라도 **메타·타임코드·출처·미확인 사항은 버리지 않는다.** 같은 폴더의 사이드카 `{NN}-{슬러그}.meta.md`로 분리한다 (`references/templates.md` §4). 대본 파일만 깨끗해지고 추적성은 유지된다.
- 모드 B의 확장자를 `.txt`로 두는 이유: 파일 안에 마크다운 문법이 하나도 없어야 하고, 확장자만 보고 모드가 구분되어야 한다.
- 모드 B에서도 **비트 구조는 그대로 설계한다.** 3단계 비트 시트와 루프 장부는 모드와 무관하게 만들고, 결과물에서 표기만 빠진다.
- 프롬프터·TTS에 그대로 넣거나 성우에게 넘길 대본이면 B, 직접 편집하며 촬영할 대본이면 A가 맞다.

**나중에 다른 모드를 더 달라고 하면 — 대본을 다시 쓰지 않는다.** 이미 확정된 문장은
그대로 두고 형태만 바꾼다. 문장을 손대면 승인받은 대본이 조용히 달라진다.

| 요청 | 하는 일 |
|---|---|
| A 있는데 "대사만 줘" | 헤딩·메타·출처를 걷어 `.txt` 로, 걷어낸 것은 `.meta.md` 로 (§4). **문장은 한 글자도 안 바꾼다** |
| A 있는데 "화면 대본도 줘" | 낭독문을 컷으로 쪼개 `.sv.md` 파생 (§5). 쪼개기만 하고 문장은 그대로 |
| B 있는데 "구조 대본으로" | `.meta.md` 를 다시 합쳐 `.md` 로 |
| 시리즈 중간에 모드 변경 | **이미 쓴 편도 전부 변환한다.** 편마다 모드가 다르면 넘길 때 사고가 난다 |

바뀐 모드는 시리즈 바이블에 다시 적어 이후 편이 따라가게 한다.
- **화면(자료화면·그래픽)까지 만들 거면 C를 함께 낸다.** 대본을 쓴 사람이 컷을 나누는 게
  가장 정확하다 — 나중에 남이 쪼개면 어디서 끊어야 할지 몰라 문장 한가운데가 잘린다.

### 2단계 — 시리즈 설계 → **승인 받기**

`references/series.md`를 읽고 시리즈 축을 고른 뒤, 아래 형태로 짧게 제시한다:

```
시리즈: 반도체 보조금 전쟁 (4편 · 롱폼 내레이션 · 편당 18분)
관통 질문: 돈을 가장 많이 쓴 나라가 왜 가장 뒤처졌나
축: 층위축 (현상 → 구조 → 이해관계 → 전망)

1편 «공장은 세워졌다, 그런데» — 핵심 질문: 준공식 이후 2년간 무슨 일이 있었나 / 반전: 지연의 원인은 돈이 아니었다 / 남기는 갈고리: 진짜 병목의 이름
2편 ...
```

편별로 **핵심 질문 / 반전 / 남기는 갈고리** 세 줄이 반드시 있어야 한다. 셋 중 하나라도 안 써지는 편은 독립된 편이 아니다 — 합치거나 축을 바꾼다.

단편 요청이거나 주제가 한 편에 담기면 시리즈 설계를 생략하고 3단계로 간다. 단, 주제가 커서 한 편으로 얕아질 것 같으면 **시리즈 분할을 먼저 제안**한다.

승인 후 `scripts/{시리즈-슬러그}/00-series.md`를 `references/templates.md` §1 형식으로 작성한다.

### 3단계 — 편별 비트 시트 → **승인 받기**

대본을 쓰기 전에 그 편의 구조를 먼저 확정한다. `references/formats.md`의 트랙 골격에 맞춰 비트(장면·블록) 단위로:

```
1편 비트 시트 (18분 / 목표 5,600자)
0:00 콜드 오픈 — 2024년 4월 그 공장의 야간 위성사진 [루프A 열기: 왜 불이 꺼져 있나]
0:40 프레이밍 — 이 영상이 답할 질문 한 문장
1:10 1막 …
```

비트마다 **열린 루프의 개/폐**를 표기한다. 열린 루프가 회수되지 않고 끝나는 비트 시트는 통과시키지 않는다.

비트 시트가 짧고 사용자가 이미 구조를 지정했다면 승인을 생략하고 집필로 넘어간다.

### 4단계 — 편별 집필 (서브에이전트 위임)

구조가 확정되면 **각 편은 서브에이전트가 쓴다.** 메인은 설계·조율·통합 검수를 맡는다. 상세 절차와 브리프 템플릿은 `references/delegation.md`.

| 상황 | 처리 |
|---|---|
| 시리즈 3편 이상 | **1편을 앵커로 먼저 확정** → 2편 이후를 한 메시지에 여러 `Agent` 호출로 병렬 위임 (동시 5편까지) |
| 시리즈 2편 | 1편 앵커 → 2편만 위임. 직접 써도 된다 |
| 단편 | 직접 쓴다. 위임 이득이 없다 |

**앵커를 먼저 쓰는 이유**: 전편을 동시에 내보내면 문체·리듬·호칭·용어 표기가 편마다 갈린다. 확정된 1편을 톤 기준으로 주고 "전문을 읽고 문체를 맞추라"고 지시하면 병렬로도 톤이 유지된다.

**위임 전 게이트** (`delegation.md` §2) — 하나라도 비면 서브가 그 자리를 자기 판단으로 메운다:
바이블 작성 완료 / **모든 편의 3요소 확정**(담당 편만이 아니라 전편 — 반전 카드 충돌 방지) / **갈고리 문장을 바이블에 문장 수준으로 확정**(병렬에서는 N편 담당이 N-1편 결과물을 못 본다) / 시리즈 전체 리서치 완료 / 비트 시트 + 루프 장부 / 출력 모드 / 앵커 편 완성.

집필 형식은 모드에 따라 고른다.

| 모드 | 쓰는 파일 | 형식 |
|---|---|---|
| A. 구조 대본 | `scripts/{시리즈-슬러그}/{NN}-{슬러그}.md` | `references/templates.md` §2 |
| B. 순수 대사 | `scripts/{시리즈-슬러그}/{NN}-{슬러그}.txt` + `{NN}-{슬러그}.meta.md` | `references/templates.md` §3, §4 |
| C. 화면 대본 | `scripts/{시리즈-슬러그}/{NN}-{슬러그}.sv.md` (A·B 와 함께) | `references/templates.md` §5 |

- 두 모드 공통: 본문은 **읽을 문장만.** `[B롤]`, `(강조)`, `※화면에` 같은 연출 지시를 낭독 문장에 섞지 않는다.
- 모드 A의 섹션 헤딩(`## [00:00–00:40] 콜드 오픈`)은 구조 표시용이며 낭독 대상이 아니다 — 템플릿 상단에 그 사실을 명시해 둔다.
- 모드 B는 헤딩·번호·불릿·강조 문법을 일절 쓰지 않는다. 비트 경계는 빈 줄 하나로만 나눈다.
- 문장 규칙·리듬·금지 표현은 `references/craft.md` §4, 트랙별 문체는 `references/formats.md` §3을 따른다.
- 목표 글자수의 ±10% 안에 들어와야 한다. 미달이면 층을 더 파고(구체 장면·수치·인물), 초과면 설명을 자르지 말고 **중복된 재설명**을 자른다.

### 5단계 — 자체 검수 (필수, 생략 금지)

`references/review.md`의 명령과 체크리스트를 실행한다. **모드 B는 §6의 전용 명령**(필터 없는 분량 계산, 마크다운 누출 검사, 사이드카 정합, 문단 구조)을 대신 쓴다. 수동 체크리스트(§5)는 모드와 무관하게 적용한다.

최소한 이 네 개는 항상 돌린다:

1. 분량 — 낭독 글자수가 목표 범위 안인지
2. 긴 문장 — 90자 초과 문장 목록 (전부 쪼갠다)
3. 금지 표현 — "알아보겠습니다", "다양한", "여러 가지" 등
4. 루프 회수 — 비트 시트에서 연 루프가 전부 닫혔는지

검수에서 걸린 항목은 **고친 뒤에** 보고한다. "걸렸지만 남겨뒀다"는 그 이유를 함께 적는다.

### 5.5단계 — 통합 검수 (메인이 직접, 시리즈일 때 필수)

서브가 각자 검수를 돌렸어도 **편간 정합은 아무도 보지 않았다.** 메인이 전편을 읽고 `references/delegation.md` §6을 실행한다: 갈고리 연결 / 관통 루프 회수 / 반전 중복 / 시그니처 유지 / 문체 드리프트(편별 평균 문장 길이) / 용어 표기 통일 / 사실 충돌 / 분량 균질성.

걸린 항목은 **해당 편 담당 서브에게 `SendMessage`로 되돌린다.** 메인이 직접 고치면 그 편만 문체가 튄다.

### 6단계 — 보고

- 생성한 파일 경로, 편별 글자수와 예상 길이
- 시리즈 관통 질문과 각 편 갈고리
- 소스에서 확인 못 해 `## 미확인 사항`에 남긴 항목 (있으면 반드시 알린다)
- 웹 검색으로 보강한 부분과 그 출처

## 1. 저장 구조

모드 A (구조 대본):

```
scripts/
  {시리즈-슬러그}/
    00-series.md              시리즈 바이블
    01-{에피소드-슬러그}.md    메타 + 타임코드 + 낭독 문장 + 출처
```

모드 B (순수 대사):

```
scripts/
  {시리즈-슬러그}/
    00-series.md               시리즈 바이블
    01-{에피소드-슬러그}.txt    낭독 문장만
    01-{에피소드-슬러그}.meta.md  메타 + 타임코드 대응 + 출처 + 미확인 사항
```

- 단편은 `scripts/single/{YYYY-MM-DD}-{슬러그}.md`(A) 또는 `.txt` + `.meta.md`(B)
- 슬러그는 한글 그대로 쓰되 공백은 `-`, 파일명에 못 쓰는 문자(`/`, `:`, `?`)는 제거
- 같은 경로에 파일이 있으면 덮어쓸지 `_v2`로 남길지 먼저 확인한다

## 3. 절대 하지 않는 것

- **인사와 채널 소개로 시작하기.** 첫 문장은 주제 안으로 바로 들어간다.
- **목차 낭독.** "먼저 A를 보고, 그다음 B를 살펴보겠습니다" — 이탈 지점 1순위다.
- **소스에 없는 수치·인용·날짜를 그럴듯하게 채우기.** 모르면 `## 미확인 사항`으로.
- **사용자가 지정하지 않은 자료를 끌어와 논지를 바꾸기.** 리서치는 방향 안에서 최신 사실을 확인하는 용도다.
- **화자의 주장을 사실처럼 쓰기.** 소스가 주장이면 대본도 "~라고 주장한다"로 남긴다.
- **열린 루프를 회수하지 않고 끝내기.** 던진 질문에 답하지 않는 편은 시청자를 배신한다.
- **연출 지시를 축어 본문에 섞기.** 필요하면 별도 섹션(A) 또는 사이드카(B)로 분리한다.
- **순수 대사 모드에서 출처를 버리기.** 대본 파일에서 빠질 뿐, 사이드카에는 반드시 남는다.
- **구조가 확정되기 전에 집필을 위임하기.** 브리프에 없는 것은 서브에게 존재하지 않는 것과 같다.
- **앵커 없이 전편을 병렬로 내보내기.** 나중에 톤을 통일하는 비용이 앵커를 먼저 확정하는 비용보다 크다.
- **통합 검수를 서브에게 맡기기.** 서브는 자기 편만 본다.
