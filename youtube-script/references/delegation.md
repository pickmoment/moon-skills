# delegation.md — 편별 집필 위임

시리즈 구조가 확정되면 각 편은 **서브에이전트가 쓴다.** 편 하나의 집필은 자기완결적이고 컨텍스트를 많이 먹으므로, 메인은 설계·조율·통합 검수를 맡고 집필은 내보낸다.

## 1. 위임 여부

| 상황 | 처리 |
|---|---|
| 시리즈 3편 이상 | **위임한다.** 1편은 앵커로 먼저, 나머지는 병렬 |
| 시리즈 2편 | 위임해도 되고 직접 써도 된다. 1편 앵커 → 2편만 위임 |
| 단편 | **직접 쓴다.** 위임 이득이 없다 |
| 편 하나만 재작업 | 그 편만 위임 (앵커는 이미 있는 다른 편) |

## 2. 위임 게이트 — 아래가 전부 확정되기 전에는 내보내지 않는다

서브에이전트는 지금까지의 대화를 모른다. **브리프에 없는 것은 존재하지 않는 것과 같다.** 위임 전에:

- [ ] `00-series.md` 작성 완료 (관통 질문, 시청자 약속, 톤, 시그니처, 출력 모드)
- [ ] **모든 편의 3요소(핵심 질문·반전·갈고리) 확정.** 담당 편만이 아니라 전편 — 반전 카드가 겹치지 않게 하려면 서브가 남의 카드를 알아야 한다
- [ ] **갈고리 문장을 바이블에 확정.** 병렬 집필에서는 N편 담당이 N-1편의 결과물을 볼 수 없다. 넘길 갈고리와 받을 회수를 **문장 수준으로** 바이블에 못 박아야 편간 연결이 어긋나지 않는다
- [ ] 시리즈 전체 리서치 완료 — 확보한 사실과 출처를 바이블 `## 소스와 리서치`에 기재
- [ ] 편별 비트 시트 작성 + 루프 장부 표기
- [ ] 출력 모드(A 구조 대본 / B 순수 대사) 결정
- [ ] **1편(앵커) 집필 완료** — 2편 이후를 내보내는 조건

게이트 하나라도 비어 있으면 서브가 그 자리를 자기 판단으로 메운다. 그게 톤 드리프트와 사실 오염의 원인이다.

## 3. 톤 앵커 — 1편을 먼저 쓰는 이유

전편을 동시에 병렬로 쓰면 문체·리듬·호칭·용어 표기가 편마다 갈린다. 그래서:

1. **1편은 단독으로 먼저 집필한다.** 메인이 직접 쓰거나, 서브에이전트 하나에게 단독 위임하고 결과를 검수해 확정한다.
2. 확정된 1편이 **톤 앵커**다. 2편 이후 브리프에 1편 파일 경로를 주고 **전문을 읽고 문체를 맞추라**고 지시한다.
3. 2편 이후는 병렬로 내보낸다.

앵커 없이 병렬로 내보낸 결과물을 나중에 통일하는 것보다, 앵커 하나를 먼저 확정하는 편이 훨씬 싸다.

## 4. 브리프 템플릿

아래를 채워 `Agent` 도구의 `prompt`로 넘긴다. `subagent_type`은 `deep-worker`(집필 판단이 많다), 편이 단순하면 `claude`.

```
당신은 유튜브 대본 집필자다. 시리즈 {시리즈 제목}의 {N}편 대본 한 편만 쓴다.

## 먼저 읽을 파일 (전부 필수)
- {스킬경로}/references/craft.md      — 깊이·몰입 기법. 집필 규칙의 본체
- {스킬경로}/references/formats.md    — 트랙 골격, 분량 환산, 문체
- {스킬경로}/references/templates.md  — 출력 파일 형식
- {스킬경로}/references/review.md     — 집필 후 실행할 검수 (명령은 assets/check.sh 하나다)
- {프로젝트}/scripts/{시리즈-슬러그}/00-series.md — 시리즈 바이블
- {프로젝트}/scripts/{시리즈-슬러그}/01-{앵커-슬러그}.{md|txt} — **톤 앵커. 전문을 읽고 문체·리듬·호칭·용어 표기를 맞춘다**

## 담당 편
- 편: {N}/{총 편수} «{제목}»
- 트랙: {롱폼 내레이션 | 토킹헤드}
- 핵심 질문: {하나}
- 반전: {사실} / 근거: {출처}
- 이 편이 남길 갈고리 (바이블 확정 문장): "{문장}"
- 전편에서 받은 갈고리 (바이블 확정 문장): "{문장}" — 콜드 오픈 뒤 1~2문장으로 회수한다. 전편을 안 본 시청자도 이해되게. 요약이 아니라 긴장 복원
- 비트 시트:
  {비트 | 타임 | 글자수 | 내용 | 루프 개폐 — 표 그대로 붙인다}

## 출력
- 모드: {A 구조 대본 | B 순수 대사} {+ C 화면 대본}
- 파일: {절대경로}
- (모드 B) 사이드카: {절대경로}.meta.md — 없이 제출하면 미완성이다
- (모드 C) 화면 대본: {절대경로}.sv.md — **대본을 확정한 뒤** 그 낭독문을 컷으로 쪼개 파생시킨다.
  문장은 한 글자도 바꾸지 않는다 (`templates.md` §5). `@stat` 컷은 숫자에 단위를 붙인다
- 배포 패키지: 대본 파일(모드 A) 또는 사이드카(모드 B) 끝에 `## 배포 패키지` (`templates.md` §6)
- 목표: {N}분 / {N,NNN}자 (허용 {하한}~{상한})

## 근거 범위 (엄수)
- 바이블 `## 소스와 리서치`에 있는 사실만 쓴다.
- 그 안에서 부족하면 **최신 정보 확인 목적의 검색만** 허용한다 (수치·날짜·현재 상황·고유명사 표기).
- 지정되지 않은 자료를 찾아와 논지를 바꾸지 않는다. 사실을 지어내지 않는다.
- 확인 못 한 사실은 대본에서 빼고 미확인 사항에 적는다.

## 금지
- 담당 편 외의 파일을 만들거나 고치지 않는다. 바이블도 수정하지 않는다.
- 다른 편에 배정된 반전을 쓰지 않는다 (바이블 반전 카드 배분 참조).
- 인사·채널 소개·목차 낭독으로 시작하지 않는다.
- 열린 루프를 회수하지 않고 끝내지 않는다. 다음 편으로 넘기는 것은 위 갈고리 문장뿐이다.
- 연출 지시를 낭독 문장에 섞지 않는다.

## 집필 후 (필수)
```bash
bash {스킬경로}/assets/check.sh {대본 절대경로}      # 모드 C도 냈으면 .sv.md 도 따로 한 번
```
**종료 코드 0 이 나올 때까지 고친다.** WARN 은 사람이 봐야 하는 항목이니 확인한 뒤 보고에 적는다.
`review.md` §2 수동 체크리스트는 모드와 무관하게 직접 훑는다.

## 반환 형식 (이 텍스트가 그대로 결과값이다 — 인사말 없이)
- 파일 경로:
- 실제 글자수 / 예상 길이:
- check.sh 종료 코드와 남은 WARN (그대로 붙인다)
- 제목 후보 3개와 고른 것:
- 콜드 오픈 첫 문장 (그대로):
- 전편 회수 문장 (그대로):
- 엔딩 갈고리 문장 (그대로):
- 사용한 반전과 근거:
- 미확인 사항:
- 검색으로 보강한 사실 + URL:
- 바이블과 어긋난 점 / 판단이 필요했던 지점:
```

## 5. 병렬 실행

- 2편 이후를 **한 메시지에 여러 `Agent` 호출**로 동시에 내보낸다.
- 동시 5편까지. 6편 이상이면 두 묶음으로 나눈다.
- 각 서브는 **자기 파일만** 쓴다. 파일 경로가 겹치지 않으므로 워크트리 격리는 불필요하다.
- 결과가 도착할 때까지 메인은 다른 일을 하지 않는다 — 수거 후 통합 검수가 바로 다음 일이다.

## 6. 수거 후 통합 검수 (메인이 직접, 생략 금지)

서브가 각자 검수를 돌렸어도 **편간 정합은 아무도 보지 않았다.** 메인이 전편을 읽고 확인한다.

- [ ] **갈고리 연결**: N편 엔딩 갈고리 문장 ↔ N+1편 회수 문장이 실제로 이어지는가. 던지고 안 받은 갈고리가 없는가
- [ ] **관통 루프**: 1편에서 던진 관통 질문이 마지막 편에서 답되는가
- [ ] **반전 중복**: 두 편이 같은 반전을 쓰지 않았는가. 앞 편이 뒤 편 카드를 미리 써버리지 않았는가
- [ ] **시그니처**: 오프닝·클로징 시그니처와 반복 장치가 전편에 유지되는가
- [ ] **문체 드리프트**: 종결어미·호칭·시제 운용이 앵커와 같은가. 편별 평균 문장 길이 편차가 크지 않은가
- [ ] **용어 표기 통일**: 같은 고유명사가 편마다 다르게 적히지 않았는가
- [ ] **사실 충돌**: 같은 수치·날짜가 편마다 다르게 적히지 않았는가
- [ ] **분량 균질성**: 편별 글자수가 목표 ±10% 안인가
- [ ] **배포 패키지**: 편별 제목이 서로 겹치지 않고, 시리즈 표기(«N편» 형식·부제)가 일관된가

위 항목 중 기계가 볼 수 있는 것 — 분량 균질성, 편별 평균 문장 길이 이탈, 바이블에 확정된
갈고리·회수 문장이 실제 대본에 있는지, 모드 B 사이드카 누락, 라틴 문자 용어 표기 빈도 — 은
한 번에 돌린다. 바이블·사이드카·화면 대본은 편 목록에서 자동으로 빠진다.

```bash
bash <스킬경로>/assets/check.sh series scripts/{시리즈-슬러그}
```

한글 고유명사는 이 명령으로 안 잡히므로 시리즈 핵심 용어 3~5개를 `grep -c` 로 편별 비교한다.
갈고리 연결·반전 중복·시그니처·사실 충돌은 **전편을 읽어야** 판정된다 — 스크립트가 대신하지 않는다.

통합 검수에서 걸린 항목은 **해당 편 담당 서브에게 되돌린다**(§7). 메인이 직접 고치면 그 편만 문체가 튄다.

## 7. 재작업

- 같은 서브에이전트에게 `SendMessage`로 수정 지시를 보낸다 — 그 편의 컨텍스트가 살아 있어 가장 싸다.
- 세션이 끊겼거나 지적 사항이 구조 수준(비트 시트를 다시 짜야 함)이면 브리프를 갱신해 새로 띄운다.
- 수정 지시에는 **무엇이 왜 틀렸는지와 어느 파일의 어느 문장인지**를 명시한다. "톤을 다듬어라" 같은 지시는 드리프트를 키운다.

## 8. 메인이 서브에게 넘기지 않는 일

- 시리즈 설계와 축 선택 (2단계)
- 반전 카드 배분과 갈고리 문장 확정
- 시리즈 전체 리서치
- 통합 검수와 사용자 보고
- 사용자와의 승인 대화

이 다섯은 시리즈 전체를 봐야 하는 일이다. 서브는 자기 편만 본다.
