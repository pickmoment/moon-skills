# templates.md — 파일 형식

## 0. 명명 규칙

```
scripts/{시리즈-슬러그}/00-series.md              시리즈 바이블

모드 A (구조 대본)
scripts/{시리즈-슬러그}/01-{에피소드-슬러그}.md
scripts/single/{YYYY-MM-DD}-{슬러그}.md

모드 B (순수 대사)
scripts/{시리즈-슬러그}/01-{에피소드-슬러그}.txt       낭독 문장만
scripts/{시리즈-슬러그}/01-{에피소드-슬러그}.meta.md   메타·출처

모드 C (화면 대본 — A 또는 B 와 **함께** 낸다)
scripts/{시리즈-슬러그}/01-{에피소드-슬러그}.sv.md     낭독문을 화면 한 컷 단위로 쪼갠 것
```

- 슬러그는 한글 그대로, 공백은 `-`. `/ : ? * " < > |`는 제거.
- 편 번호는 두 자리 (`01`, `02`). 시리즈 바이블은 항상 `00-series.md`.

## 1. 시리즈 바이블 — `00-series.md`

````markdown
# {시리즈 제목}

- 트랙: {롱폼 내레이션 | 토킹헤드}
- 편수: {N}편
- 편당 길이: {N}분 (목표 {N,NNN}자)
- 축: {층위축 | 연대기축 | 인물축 | 질문축 | 사례축}
- 출력 모드: {A 구조 대본 | B 순수 대사} {+ C 화면 대본} — 모든 편에 동일 적용
- 작성: {YYYY-MM-DD}

## 관통 질문

{시리즈 전체가 답하는 질문 한 문장. 마지막 편에서 회수된다.}

## 시청자 약속

{다 보고 나면 무엇을 알게 되는가. 한 문장. 이 약속을 못 지키는 편은 잘라낸다.}

## 톤

- 시점: {3인칭 관찰 | 1인칭}
- 감정: {억제 | 표현 허용}
- 대상: {이 주제를 처음 접하는 사람 / 이미 아는 사람}
- 금지: {이 시리즈에서 특별히 쓰지 않을 표현·구성}

## 시그니처

- 오프닝: {콜드 오픈 직후 매 편 고정으로 들어가는 한 문장}
- 클로징: {매 편 마지막 고정 문장 또는 형식}
- 반복 장치: {매 편 같은 자리에 오는 형식적 장치}

## 에피소드

### 1편 «{제목}»
- 핵심 질문: {하나}
- 반전: {기존 이해를 뒤집는 사실 + 근거}
- 갈고리 문장: "{다음 편으로 넘길 실제 문장. 병렬 집필의 편간 연결이 이 문장에 걸려 있으므로 요약이 아니라 낭독될 문장으로 적는다}"
- 회수 문장: "{전편 갈고리를 받는 실제 문장. 1편은 '해당 없음'}"
- 상태: {설계 | 리서치 완료 | 앵커 확정 | 집필 완료 | 통합 검수 완료}
- 집필: {메인 | 서브에이전트}

### 2편 «{제목}»
...

## 소스와 리서치

- 사용자 전달 내용: {받은 문서·텍스트·링크·구두 설명. 이 시리즈 논지의 출처}
- 사용자가 정한 방향성: {무엇을 말하려는 시리즈인가. 리서치는 이 방향을 벗어나지 않는다}
- 최신 정보 확인 항목: {검색으로 확인·갱신한 수치·날짜·현재 상황 + URL}
- 반전 카드 배분: {어느 반전을 몇 편에 쓰는지 — 앞 편에서 다 쓰지 않도록}
- 미확인: {확인 못 한 사실. 편 집필 전에 채우거나 대본에서 뺀다}
````

## 2. 모드 A · 구조 대본 — `{NN}-{슬러그}.md`

**본문은 낭독 원고다.** 섹션 헤딩(`## [00:00–00:40] 콜드 오픈`)은 구조 표시용이며 읽지 않는다.
헤딩 아래 문장은 전부 그대로 소리 내 읽는 문장이다. 연출 지시·괄호 주석을 본문에 섞지 않는다.

````markdown
# {N}편 «{제목}»

- 시리즈: {시리즈 제목} ({N}/{총 편수})
- 트랙: {롱폼 내레이션 | 토킹헤드}
- 목표: {N}분 / {N,NNN}자 · 실제: {N,NNN}자
- 핵심 질문: {하나}
- 반전: {한 줄}
- 루프 장부: A(0:00 열기 → 14:10 닫기) / B(3:20 열기 → 8:40 닫기) / 갈고리(17:30 열기 → 다음 편)

---

## [00:00–00:40] 콜드 오픈

{낭독 문장. 장면 투척·모순·판돈 중 하나.}

## [00:40–01:10] 프레이밍

{이 편이 답할 질문 한 문장 + 결론 방향만 흘리는 문장.}

## [01:10–05:00] 1막 · {비트 제목}

{낭독 문장.}

## [05:00–12:00] 2막 · {비트 제목}

{낭독 문장.}

## [12:00–13:30] 전환점 · {반전 제목}

{낭독 문장.}

## [13:30–17:00] 3막 · {비트 제목}

{낭독 문장.}

## [17:00–18:00] 클로징

{프레이밍 질문에 답하는 문장 + 한 단계 확대 + 갈고리.}

---

## 출처

- {대본에 등장한 수치·인용·날짜}: {소스 파일 경로 또는 URL}
- {…}

## 미확인 사항

- {찾지 못해 대본에서 뺀 사실. 없으면 "없음"}

## 연출 메모

{선택. 낭독과 무관한 촬영·자료화면 아이디어가 있으면 여기에만 적는다. 본문에는 절대 섞지 않는다.}

## 배포 패키지

{§6 형식. 제목 후보 3개 · 썸네일 문구 · 설명문 · 챕터 마커}
````

- 타임코드는 비트 시트에서 계산한 값을 그대로 적는다. 집필 후 글자수가 바뀌면 타임코드도 갱신한다.
- 토킹헤드 트랙은 헤딩을 `## [01:10–04:00] 블록 1 · {주장}` 형식으로 쓴다.
- `## 출처`는 대본에 등장한 **모든** 수치·인용·고유명사를 덮어야 한다 (`review.md` §4).

## 3. 모드 B · 순수 대사 — `{NN}-{슬러그}.txt`

**파일 안에 낭독하지 않는 글자가 하나도 없어야 한다.**

들어가지 않는 것: 제목, 편 번호, 타임코드, 섹션 이름, 마크다운 헤딩·불릿·강조·구분선, 괄호 주석, 연출 지시, 출처 표기, 화자 라벨.
들어가는 것: 읽을 문장. 그리고 문단을 나누는 빈 줄.

```
2024년 4월 3일 새벽 두 시, 애리조나의 그 공장은 불이 꺼져 있었습니다. 준공식은 이미 열여덟 달 전에 끝났습니다.

돈을 가장 많이 쓴 나라가 왜 가장 뒤처졌을까요. 답은 보조금이 아니라 전기에 있었습니다.

그해 여름으로 돌아가 보겠습니다.
```

- **문단 = 호흡 단위.** 빈 줄 하나로 나눈다. 3~5문장이 한 문단.
- **비트 경계도 빈 줄 하나.** 빈 줄을 두 개 넣어 구간을 구분하고 싶은 충동을 참는다 — 도구에 따라 공백이 낭독 침묵으로 처리되면 의도치 않은 간격이 생긴다.
- 숫자·단위·외국어는 **읽을 대로** 적는다. `520억 달러`처럼 읽는 방식이 하나뿐이면 그대로, `TSMC`처럼 갈리면 `티에스엠씨`로. TTS에 넣을 대본이면 이 원칙을 특히 엄격히 적용한다.
- **한글로 풀어 쓴 수(`두 곳`, `열여덟 달`)는 사이드카 `## 출처`에 아라비아 숫자를 병기한다** — `2곳(두 곳): {URL}`. 대본 쪽 표기만 남기면 수치 대조가 통째로 빠져나간다 (`review.md` §1).
- 강조하고 싶은 단어에 `**`를 쓰지 않는다. 강조는 문장 구조와 어순으로 만든다.
- 파일 인코딩은 UTF-8, 끝에 개행 하나.

## 4. 모드 B 사이드카 — `{NN}-{슬러그}.meta.md`

순수 대사 파일에서 빠진 정보는 전부 여기 남는다. **이 파일 없이 모드 B 대본을 납품하지 않는다.**

````markdown
# {N}편 «{제목}» — 메타

- 대본 파일: `{NN}-{슬러그}.txt`
- 시리즈: {시리즈 제목} ({N}/{총 편수})
- 트랙: {롱폼 내레이션 | 토킹헤드}
- 목표: {N}분 / {N,NNN}자 · 실제: {N,NNN}자
- 핵심 질문: {하나}
- 반전: {한 줄}

## 비트 대응

대본 파일의 각 비트가 몇 번째 문단에서 시작하는지 적는다. 타임코드를 대본에 못 넣으므로 이 표가 그 역할을 한다.

| 비트 | 타임 | 시작 문단 | 첫 문장 앞부분 |
|---|---|---|---|
| 콜드 오픈 | 00:00–00:40 | 1 | "2024년 4월 3일 새벽 두 시…" |
| 프레이밍 | 00:40–01:10 | 2 | "돈을 가장 많이 쓴 나라가…" |
| 1막 · {제목} | 01:10–05:00 | 3 | "그해 여름으로…" |

## 루프 장부

- A: 문단 1에서 열기 → 문단 {N}에서 닫기
- B: 문단 {N}에서 열기 → 문단 {N}에서 닫기
- 갈고리: 문단 {N}에서 열기 → 다음 편

## 출처

- {대본에 등장한 수치·인용·날짜}: {소스 또는 URL}

## 미확인 사항

- {찾지 못해 대본에서 뺀 사실. 없으면 "없음"}

## 연출 메모

{선택. 촬영·자료화면 아이디어}

## 배포 패키지

{§6 형식. 제목 후보 3개 · 썸네일 문구 · 설명문 · 챕터 마커}
````

- 비트 대응 표의 **문단 번호는 집필이 끝난 뒤 실제 파일을 세어 적는다.** 추정하지 않는다.
- 대본을 고치면 사이드카의 문단 번호와 실제 글자수도 함께 갱신한다.

## 5. 모드 C · 화면 대본 — `{NN}-{슬러그}.sv.md`

`scriptviz` 스킬이 그대로 읽는 형식이다. **A 로 대본을 완성한 뒤 컷으로 쪼개 파생시킨다.**

````markdown
---
title: 돈을 가장 많이 쓴 나라가 왜 뒤처졌나
theme: midnight
cps: 5.2
---

# 돈을 가장 많이 쓴 나라가 왜 뒤처졌나

## 1장 · 콜드 오픈

[00:00] 2021년 그 나라는 반도체에 520억 달러를 걸었습니다.

@stat 3년이 지난 지금까지 실제로 집행된 돈은 12억 달러입니다.

((여기서 잠깐 쉰다 — 숫자가 앉을 시간))

## 2장 · 무슨 일이 있었나

![2024년 겨울, 착공만 하고 멈춘 부지](shots/factory.png)
공사는 시작됐지만 장비는 들어오지 않았습니다.

@flow 돈이 움직인 경로는 셋이었습니다. 신청, 심사, 그리고 집행.

@split ![](shots/factory.png)
남은 건 콘크리트와 계약서뿐이었습니다.
````

### 문법

| 쓰는 것 | 뜻 |
|---|---|
| **빈 줄로 나뉜 문단 하나** | **화면 한 컷.** 이게 이 형식의 전부다 |
| `---` frontmatter | `title` · `theme`(midnight·paper·neon·warm) · `cps`(낭독 속도) |
| `# 제목` | 앞에 타이틀 화면이 하나 생긴다 |
| `## 1장 · …` | 여기부터 그 챕터. 화면 위에 표시된다 |
| `[MM:SS]` | 절대 타임코드. 추정보다 우선한다 |
| `@stat` `@flow` `@compare` `@hero` … | 장면 타입 지정 (19종) |
| `((메모))` | 연출 메모. 화면에 안 나오고 발표자 패널에만 |
| `![캡션](경로)` | 화면 전체 사진 + 캡션 |
| `@split ![](경로)` | 왼쪽은 말, 오른쪽은 사진 |

### 어디서 끊나

**A 의 비트(콜드 오픈·1막…)는 수백 자 덩어리다. C 의 비트는 화면 한 컷이다** —
2~10초, 스무 자에서 예순 자쯤. 한 문단을 컷 여러 개로 쪼개야 한다.

끊는 자리는 셋이다.

- **주어가 바뀔 때** — "정부는 520억을 걸었다" / "기업은 착공만 했다"
- **숫자가 나올 때** — 숫자는 그 자체로 한 컷이다 (`@stat`)
- **호흡이 바뀔 때** — 긴 설명 뒤 짧은 단언

한 컷에 두 가지를 말하지 않는다. 낭독 2초를 못 채우는 컷도 만들지 않는다
(`scriptviz` 가 최소 2.2초를 준다).

### 장면 타입을 고르는 기준

전부 적을 필요는 없다 — **안 적으면 문장 모양을 보고 초안을 고른다.** 다만 아래는
직접 적는 게 낫다.

| 낭독 내용 | 지정 |
|---|---|
| 숫자 하나가 핵심 | `@stat` |
| A → B → C 경로 | `@flow` |
| 둘을 맞세움 | `@compare` |
| 비율·구성 | `@donut` · `@bars` |
| "백 명 중 마흔한 명" | `@pictograph` |
| 남의 말 | `@quote` |
| 단언 한 문장 | `@hero` |

**`@stat` 컷은 숫자에 단위가 붙어 있어야 카드가 만들어진다.** scriptviz 가 뽑는 것은
`숫자 + 단위` 짝이고, 아는 단위는 `% 퍼센트 배 억 만 천 명 원 건 위` 다. `두 곳`처럼 한글로
풀어 쓰거나 `2곳`처럼 목록에 없는 단위를 쓰면 **값이 `00` 인 빈 카드**가 나온다.
낭독 표기를 지켜야 하면 `@hero` 로 바꾼다. `check.sh` 가 파싱 결과를 보고 FAIL 로 잡는다.

나머지 판단(리듬·같은 장면 연속·읽을 시간)은 `scriptviz` 의 `validate` 가 잡아준다.

### 넘긴 뒤

```bash
node <scriptviz>/assets/sv.js 01-보조금.sv.md --json > draft.json   # 초안 확인
node <scriptviz>/assets/sv.js 01-보조금.sv.md deck.html             # 바로 빌드
```

이미지 경로는 **이 파일이 있는 폴더 기준**이고, 빌드할 때 data URI 로 박혀 단일 파일이
된다. 화면을 다듬는 일부터는 `scriptviz` 스킬이 이어받는다.

### 검수

```bash
bash <스킬경로>/assets/check.sh 01-공장은-세워졌다.sv.md
```

파싱 성공, 2.2초 미만 컷, 숫자 없는 `@stat`, 같은 장면 4연속, 그리고 **원본 대본과 낭독문이
같은지**를 본다. 마지막 항목이 이 모드의 핵심이다 — C 는 쪼개기만 하고 문장을 바꾸지 않는다.

## 6. 배포 패키지 — `## 배포 패키지`

대본만으로는 영상이 클릭되지 않는다. 제목·썸네일은 콜드 오픈보다 **앞선 이탈 지점**이고,
그 재료(콜드 오픈 문장·반전·수치)는 대본을 쓴 직후가 가장 신선하다. 모드 A 는 대본 파일
끝에, 모드 B 는 사이드카에 붙인다. 문구 규칙은 `craft.md` §9.

````markdown
## 배포 패키지

### 제목 후보

1. {숫자형 — 수치를 앞에 세운다}
2. {모순형 — 양립 불가능한 두 사실}
3. {질문형 — 프레이밍 질문의 축약}

- 고른 것: {N번} / 이유: {한 줄}

### 썸네일 문구

- 큰 글자 (7자 이내): {제목을 반복하지 않는다}
- 작은 글자 (선택): {}

### 설명문

{첫 두 줄이 검색·미리보기에 노출된다. 프레이밍 질문 한 문장 + 이 편이 답하는 범위 한 문장.}

{시리즈면 전편·다음 편 자리}

출처
- {대본 `## 출처` 에서 시청자가 직접 확인할 만한 것만 추린다}

### 챕터 마커

00:00 {비트 제목 — 목차가 아니라 궁금해지는 이름}
00:40 {}
````

- 제목은 **대본이 실제로 답하는 것만** 약속한다. 대본에 없는 반전을 제목에 걸면 이탈이 아니라 신뢰가 깨진다.
- 챕터 이름을 "서론·본론·결론"으로 쓰지 않는다. 비트 제목을 그대로 쓰되 결론을 흘리지 않는다.
- 배포 패키지는 **대본 확정 후에 쓴다.** 제목을 먼저 정하면 대본이 제목을 변호하는 글이 된다.
