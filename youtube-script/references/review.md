# review.md — 납품 전 검수

집필 직후 실행한다. **기계가 볼 수 있는 것은 전부 `assets/check.sh` 가 본다.** 문서에 명령을 옮겨 적지 않는다 — 명령이 두 군데 있으면 한쪽이 반드시 뒤처진다.

## 0. 한 번에 (필수, 생략 금지)

```bash
bash <스킬경로>/assets/check.sh scripts/반도체-보조금-전쟁/01-공장은-세워졌다.md
```

- **모드는 확장자로 정해진다.** `.md` → A(구조 대본) · `.txt` → B(순수 대사) · `.sv.md` → C(화면 대본).
- 목표 글자수와 트랙은 파일 메타(`목표: 18분 / 5,600자`, `트랙: 롱폼 내레이션`)에서 읽는다. 모드 B·C 는 짝이 되는 `.meta.md` / `.md` 에서 읽는다. 없으면 `--target 5600 --track long|talk` 로 준다.
- **종료 코드 0 이 나올 때까지 고친다.** `FAIL` 이 하나라도 있으면 납품 전 상태다.
- `WARN` 은 자동으로 판정할 수 없어 사람이 봐야 하는 것들이다. 무시하지 말고 **확인했다는 사실을 보고에 적는다.**

시리즈 전체는:

```bash
bash <스킬경로>/assets/check.sh series scripts/반도체-보조금-전쟁
```

## 1. check.sh 가 보는 것

| 검사 | 판정 | 모드 |
|---|---|---|

**한글 수치 WARN 을 그냥 넘기지 않는다.** 낭독 대본은 `두 곳`, `열여덟 달`처럼 읽을 대로 적는 게 원칙이라(`templates.md` §3) 수치 자동 대조를 빠져나간다. 출처 항목에는 **아라비아 숫자를 병기**해 둔다 — `2곳(두 곳): {URL}`. 그래야 다음 사람이 대조할 수 있다.

`series` 는 여기에 더해: 편별 분량·평균 문장 길이 표, 시리즈 평균에서 15% 이탈한 편(문체 드리프트), 바이블에 확정된 갈고리·회수 문장이 실제 대본에 있는지, 모드 B 사이드카 누락, 라틴 문자 용어 표기 빈도를 본다. 바이블(`00-series.md`)·사이드카·화면 대본은 편 목록에서 제외된다.

## 2. 수동 체크리스트 (스크립트가 못 보는 것)

### 오프닝
- [ ] 첫 문장이 20자 내외 단문이고, 고유명사나 숫자가 들어 있다
- [ ] 첫 문장에 결론이 없다
- [ ] 인사·채널 소개·목차 낭독이 없다
- [ ] 프레이밍이 이 편의 질문을 한 문장으로 말한다 (결론 방향만 흘리고 내용은 감춤)

### 루프
- [ ] 비트 시트에서 연 루프가 전부 닫혔다 (다음 편으로 넘기는 갈고리는 명시적으로 선언됨)
- [ ] 90~120초마다 루프가 열리거나 닫히는 사건이 있다
- [ ] 동시에 열려 있는 루프가 3개를 넘지 않는다

### 깊이
- [ ] 층 4단계(표면 → 메커니즘 → 원인 → 파급)까지 내려갔다
- [ ] 반전 층이 최소 1개 있고 근거가 함께 있다
- [ ] 구체성 '장면' 단계(사람·시간·행동이 있는 서술)가 3회 이상
- [ ] "N가지 이유" 식 나열로 대체된 구간이 없다
- [ ] 같은 구조의 문단이 3개 연속되는 구간이 없다

### 리텐션
- [ ] 30초 분량마다 새 정보(사실·수치·이름·장면)가 최소 1개
- [ ] 챕터 전환이 "다음으로"가 아니라 새 질문으로 이뤄진다
- [ ] 설명이 2분 넘게 이어지는 구간에 사례나 반론이 끼어 있다
- [ ] 반전 뒤에 호흡 구간이 있다

### 신뢰
- [ ] 시청자가 반박할 지점을 대본이 먼저 말하고 답한다
- [ ] 감정을 형용사로 지시하지 않는다 (사실 배치로 만든다)
- [ ] 추측을 사실처럼 쓴 문장이 없다
- [ ] 소스가 화자의 주장인 사실은 대본에서도 "~라고 주장합니다"로 되어 있다

### 엔딩
- [ ] 요약 나열이 아니다
- [ ] 프레이밍 질문으로 돌아가 한 문장으로 답한다
- [ ] 마지막 2~3문장이 한 단계 확대된다
- [ ] (시리즈) 갈고리가 예고가 아니라 질문이다
- [ ] 구독 요청이 있다면 클로징 문장 뒤에 한 문장으로만

### 시리즈 정합 (2편 이후)
- [ ] 콜드 오픈 뒤 전편 회수가 1~2문장이고, 전편을 안 본 사람도 이해된다
- [ ] 회수가 요약이 아니라 긴장 복원이다
- [ ] 전편 갈고리를 실제로 받았다
- [ ] 시그니처(오프닝·클로징 문구, 반복 장치)가 유지된다
- [ ] 이 편의 반전이 바이블의 반전 배분과 일치한다 (카드를 앞당겨 쓰지 않았다)

### 배포 패키지 (`craft.md` §9)
- [ ] 제목 후보 3개가 서로 다른 각도다 (숫자형·모순형·질문형)
- [ ] 제목이 대본 안에서 실제로 답해지는 것만 약속한다
- [ ] 썸네일 문구가 제목을 반복하지 않는다
- [ ] 챕터 이름이 목차 낭독이 아니라 비트 제목이다

## 3. 모드별 마무리

**모드 B** — `check.sh` 가 출력한 실제 문단 번호를 사이드카의 비트 대응 표에 옮겨 적는다. 추정하지 않는다. 대본을 고치면 문단 번호와 실제 글자수를 함께 갱신한다.

**모드 C** — 파싱을 통과했으면 실제로 빌드해 눈으로 본다. 화면을 다듬는 일부터는 `scriptviz` 스킬이 이어받는다.

```bash
node <scriptviz>/assets/sv.js 01-공장은-세워졌다.sv.md deck.html
```

## 4. 낭독 테스트

체크리스트를 통과했어도 마지막으로 **소리 내 읽는다고 가정하고** 전문을 다시 읽는다.
혀가 걸리는 문장, 숨이 막히는 문장, 동음이의어로 헷갈릴 문장("전자"가 電子인지 前者인지)을 고친다.
숫자는 읽는 방식이 확정돼 있어야 한다 — "520억 달러"를 어떻게 읽을지 애매하면 대본에 읽을 대로 적는다.
