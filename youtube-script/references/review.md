# review.md — 납품 전 검수

집필 직후 실행한다. **기계가 볼 수 있는 것은 전부 `assets/check.sh` 가 본다.** 문서에 명령을 옮겨 적지 않는다 — 명령이 두 군데 있으면 한쪽이 반드시 뒤처진다.

## 0. 한 번에 (필수, 생략 금지)

```bash
bash <스킬경로>/assets/check.sh scripts/반도체-보조금-전쟁/01-공장은-세워졌다.md
```

- **모드는 확장자로 정해진다.** `.md` → A(구조 대본) · `.txt` → B(순수 대사) · `.sv.md` → C(화면 대본).
- 목표 글자수와 트랙은 파일 메타(`목표: 18분 / 5,600자`, `트랙: 롱폼 내레이션`)에서 읽는다. 모드 B·C 는 짝이 되는 `.meta.md` / `.md` 에서 읽는다. 없으면 `--target 5600 --track <트랙>` 으로 준다 — `long` · `talk` · `recall` · `predict` · `duo`.
- **트랙에 따라 검사 항목이 달라진다.** 트랙을 잘못 읽으면 분량 판정(CPS)과 평균 문장 길이 기준이 통째로 어긋나고, C·D·E 전용 검사가 아예 돌지 않는다. 첫 줄에 찍히는 `(모드 A · 트랙 인출 훈련형 · …)` 를 확인한다.
- **종료 코드 0 이 나올 때까지 고친다.** `FAIL` 이 하나라도 있으면 납품 전 상태다.
- `WARN` 은 자동으로 판정할 수 없어 사람이 봐야 하는 것들이다. 무시하지 말고 **확인했다는 사실을 보고에 적는다.**

시리즈 전체는:

```bash
bash <스킬경로>/assets/check.sh series scripts/반도체-보조금-전쟁
```

**멈춤 회계는 분량 판정의 일부다.** C·D의 목표 글자수는 총 길이가 아니라 **낭독 시간**에서
나온다 (`formats.md` §1). 스크립트는 헤딩에서 멈춤 초를 더해 `총 길이 ≈ N.N분` 을 따로 찍는다 —
이 값이 기획한 편 길이와 맞는지 눈으로 확인한다.

**글자수는 NFC 기준이다.** 한글 자모가 분해된 NFD 로 저장된 파일은 `한` 한 글자가 3자로 세어져
분량이 두 배 넘게 부풀려진다. macOS 에서 파일명을 긁어오거나 일부 앱에서 복사할 때 생긴다.
스크립트는 계산 전에 NFC 로 맞추고 WARN 을 띄운다 — **파일 자체도 NFC 로 저장한다.** 편집기·
프롬프터·TTS 가 저마다 다르게 처리해 사고가 난다.

**한글 수치 WARN 을 그냥 넘기지 않는다.** 낭독 대본은 `두 곳`, `열여덟 달`처럼 읽을 대로 적는 게 원칙이라(`templates.md` §3) 수치 자동 대조를 빠져나간다. 출처 항목에는 **아라비아 숫자를 병기**해 둔다 — `2곳(두 곳): {URL}`. 그래야 다음 사람이 대조할 수 있다.

`series` 는 여기에 더해: **트랙 일관성**(전편이 같은 트랙인가 — C+D 혼합만 마지막 편 전이 검사로 허용),
트랙 C·D 시리즈면 바이블 `## 인출 설계`(질문 은행) 존재와 편별 Q·↻·A·P·R·⏸ 개수 표,
트랙 E 시리즈면 바이블 `## 화자` 존재와 편별 라벨 목록, 편별 분량·평균 문장 길이 표, 시리즈 평균에서 15% 이탈한 편(문체 드리프트), 바이블에 확정된 갈고리·회수 문장이 실제 대본에 있는지, 모드 B 사이드카 누락, 라틴 문자 용어 표기 빈도를 본다. 바이블(`00-series.md`)·사이드카·화면 대본은 편 목록에서 제외된다.

## 3. 모드별 마무리

**모드 B** — `check.sh` 가 출력한 실제 문단 번호를 사이드카의 비트 대응 표에 옮겨 적는다. 추정하지 않는다. 대본을 고치면 문단 번호와 실제 글자수를 함께 갱신한다.

**트랙 C·D** — 멈춤 합계를 더한 총 길이가 기획한 편 길이와 맞는지 확인한다. 스크립트가
`멈춤 N초 포함 총 길이 ≈ N.N분` 으로 찍어준다. 어긋나면 목표 글자수를 다시 계산한다
(`formats.md` §1 멈춤 회계).

**트랙 E** — 라벨은 글자수에서 자동으로 빠진다. 발언 비중 표를 보고 한쪽이 8:2를 넘지 않는지 본다.

**모드 C** — 파싱을 통과했으면 실제로 빌드해 눈으로 본다. 화면을 다듬는 일부터는 `scriptviz` 스킬이 이어받는다.

```bash
node <scriptviz>/assets/sv.js 01-공장은-세워졌다.sv.md deck.html
```

## 4. 낭독 테스트

체크리스트를 통과했어도 마지막으로 **소리 내 읽는다고 가정하고** 전문을 다시 읽는다.
혀가 걸리는 문장, 숨이 막히는 문장, 동음이의어로 헷갈릴 문장("전자"가 電子인지 前者인지)을 고친다.
숫자는 읽는 방식이 확정돼 있어야 한다 — "520억 달러"를 어떻게 읽을지 애매하면 대본에 읽을 대로 적는다.

**트랙 C·D는 멈춤까지 넣어 읽는다.** 질문을 읽고 실제로 4초를 세어 본다. 4초가 길게 느껴지면
질문이 너무 쉬운 것이고, 답이 안 떠오르면 너무 어려운 것이다.
**트랙 E는 두 사람 몫을 번갈아 읽는다.** 혼자 읽어도 주고받기 리듬이 살아 있어야 한다 —
한 발언이 길어 숨이 차면 그 발언은 3문장을 넘긴 것이다.
