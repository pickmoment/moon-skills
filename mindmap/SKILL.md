# mindmap

중심 주제에서 갈라지는 내용을 마인드맵으로 그린다. **트리만 쓰면 좌표·크기·줄바꿈·
색 배정은 라이브러리가 전부 계산한다.** 위치를 직접 지정할 수 없고, 지정할 필요도 없다.

## 이 스킬인가, visualthink인가

| 상황 | 쓸 것 |
|---|---|
| 깊이 3단계 이상, 노드 수십 개, 접었다 펴며 탐색 | **이 스킬** |
| 갈래 4~8개에 자식 1단계뿐인 그림 한 컷 | `visualthink` 의 `mindmap` 블록 |
| 마인드맵이 다른 도해들과 한 장에 같이 있어야 함 | `visualthink` (이 스킬의 SVG를 넣어도 된다) |
| 순서·대립·2축 평가 | 마인드맵이 아니다. `visualthink` 의 `steps`/`compare`/`matrix` |

팔레트와 글꼴은 `visualthink` 와 같으므로 두 산출물을 같은 문서에 섞어도 톤이 어긋나지 않는다.

## 워크플로

0. **만들기 전에 용도와 테마를 확인한다. 분량은 내용에서 정한다.**

   시각 산출물은 다 만든 뒤에 "다른 톤이었으면" 하는 일이 잦다. 스펙은 그대로 두고
   출력만 바꾸면 되므로, 용도와 테마는 먼저 정하고 시작한다.

   **사용자가 이미 말했다면 묻지 않는다.** "발표자료로", "손그림으로", "접었다 펼 수
   있게" 같은 단서가 있으면 그대로 따르고 바로 만든다. 단서가 없을 때만
   `AskUserQuestion` 으로 **한 번에 두 질문**을 묻는다.

   | 질문 | 선택지 |
   |---|---|
   | 어디에 쓸 건가요? | **탐색**(접기·검색 되는 뷰어) · **발표**(카메라가 갈래를 하나씩) · **문서**(정적 한 장 HTML) · **임베드**(SVG를 다른 문서에) |
   | 어떤 톤으로? | **sketch**(손그림) · **flat**(깔끔한 벡터) · **editorial**(명조 에디토리얼) · **bold**(볼드 포스터) |

   용도별 추천 테마는 `references/theming.md`. 출력은 용도에 따라 갈린다 —
   탐색은 `MM.toInteractive`, 발표는 `MM.toPresentation`, 문서는 `MM.toHTML`,
   임베드는 `MM.render`. **넷 다 같은 스펙을 받는다.** 나중에 바뀌어도 스펙을 다시
   쓰지 말고 호출만 바꾼다.

   **정적 출력에서는 클릭으로 접히지 않는다** — 그림 한 장이기 때문이다. 사용자가
   접었다 펴며 볼 것 같으면 `toInteractive` 로 주고, 무엇을 준 것인지 함께 말해준다.

   **분량은 묻지 않고, 내용이 정하게 둔다.** 사용자가 아는 것은 "이걸 마인드맵으로
   보고 싶다"까지고, 얼마나 필요한지는 내용을 읽은 쪽이 안다. 원본을 훑어 **살아남아야
   할 논점을 빠짐없이 세운 다음**, 그 결과에 맞는 `density`(`brief`/`standard`/`detailed`)
   를 스펙에 적는다. 채우려고 갈래를 부풀리지도, 줄이려고 필요한 갈래를 버리지도 않는다.
   많으면 **층위를 올리거나(형제를 상위 갈래로 묶는다), 접어두거나(`collapsed`),
   맵을 나눈다.** 예산 표와 판단 기준은 `references/composition.md`.

1. **필요한 레퍼런스만 읽는다.** 기억에 의존해 JSON을 쓰지 않는다. 네 개로 나뉘어
   있으니 통째로 읽지 말고 그 판단에 필요한 것만 연다.

   | 파일 | 언제 |
   |---|---|
   | `references/composition.md` | 마인드맵이 맞는 내용인지, 어떤 레이아웃인지, 얼마나 담을지, 흔한 실수 |
   | `references/spec.md` | 트리와 노드 필드, 픽토그램·상태·진행률·태그·교차 연결선, 색 규칙, 길이 예산 |
   | `references/theming.md` | 테마 4종, 배경 분위기 레이어·범례, 그래픽 요소의 절제 |
   | `references/api.md` | `validate`/`render`/`toHTML`/`toInteractive`, CLI, 마크다운 문법, 조작키 |

   보통은 `composition.md` 로 구조를 정하고 `spec.md` 로 스펙을 쓰면 끝난다.

2. **빈 화면에서 시작하지 않는다.** `assets/examples/` 에 완성된 것 세 개가 있다 —
   `starter-concept.json`(개념 분해·양쪽 배치), `starter-project.json`(계획·오른쪽
   배치·노트/배지/접힘), `starter-outline.md`(마크다운 아웃라인). 가까운 것을 열어
   내용을 갈아끼우는 편이 처음부터 쓰는 것보다 빠르고 덜 틀린다.

   **아웃라인이 이미 있거나 머릿속에서 목록으로 나오는 내용이면 마크다운으로 쓴다.**
   `MM.fromMarkdown` 이 트리로 바꿔준다 — 문법은 `references/api.md`.

3. **스펙을 쓰고 반드시 검증한다.**

   ```js
   const MM = require('<skill>/assets/mindmap.js');
   const check = MM.validate(spec);
   if (!check.ok) { /* check.errors 를 보고 스펙을 고친다 */ }
   if (check.warnings.length) console.warn(check.warnings);   // 길이·갈래 수·노드 수

   fs.writeFileSync('map.html',  MM.toInteractive(spec, { theme }));   // 탐색
   fs.writeFileSync('deck.html', MM.toPresentation(spec, { theme }));  // 발표
   fs.writeFileSync('map.html',  MM.toHTML(spec, { theme }));          // 문서
   const svg = MM.render(spec, { theme });                             // 임베드
   ```

   한 줄로 끝내려면 CLI도 있다:
   `node <skill>/assets/mm.js outline.md map.html --interactive --theme sketch`

4. **결과를 눈으로 확인한다.** 시각 산출물이라 렌더 성공만으로는 부족하다.
   agent-browser 스킬로 열어 스크린샷을 찍고 겹침·잘림·치우침을 점검한 뒤 전달한다.
   agent-browser를 쓸 수 없으면 확인하지 못했다고 말하고 넘긴다 — 안 본 것을 본 것처럼
   넘기지 않는다.

## 기억할 것

- **라벨은 명사구로.** 문장은 `note` 에. 라벨 20자·노트 40자(`standard` 기준)를
  넘기면 글자가 줄어들고, 줄어든 글자는 읽히지 않는다.
- **색은 depth 1 갈래에만 지정한다.** 자식은 물려받고, 그 색이 소속을 말해준다.
  잎마다 색을 주면 그 신호가 사라진다. 의미가 있을 때만 직접 지정한다.
- **루트는 비워두면 중립색이 된다.** 루트에 강한 색을 주면 갈래 색과 경쟁한다.
- **그래픽은 신호일 때만.** 밋밋해 보이는 이유는 보통 장식이 없어서가 아니라 위계가
  안 보여서다. 층위와 색을 먼저 손보고, 그다음 아이콘·상태·진행률을 얹는다.
  **한 맵에 두 종류까지** — 아이콘+상태까지는 읽히고, 거기에 진행률·태그·썸네일까지
  겹치면 무엇을 봐야 할지 알 수 없게 된다.
- **아이콘은 갈래(depth 1)에 먼저.** 잎마다 달면 아이콘이 배경이 된다.
  `"icon": "돈"` 처럼 한글로도 부른다.
- **접기는 편집이 아니라 연출이다.** `collapsed` 로 처음 보이는 층을 정하고,
  나머지는 보는 사람이 열게 둔다. 정적 출력에서는 갯수 배지만 남는다.
- **`mark` 는 한 장에 한두 개.** 강조는 대비로 작동한다.
- **깊이는 내용의 층위를 따른다.** 상한은 없다 — 필요하면 5, 6단계까지 내려간다.
  깊이를 줄이려고 하위 층을 라벨 하나에 요약해 넣지 않는다. 한 장이 너무 넓어지면
  깊이를 깎는 대신 `collapsed` 로 접어두거나 갈래를 별도 맵으로 나눈다.
- 테마는 스펙을 바꾸지 않고 `theme` 만 바꾼다. `editorial`·`bold` 는 타이포 중심이라
  라벨이 짧을수록 좋다.

## 산출물

세 호출 모두 같은 스펙을 받는다. 옵션과 조작키는 `references/api.md`.

- `MM.toInteractive(spec)` — **탐색을 요청받으면 이것.** 라이브러리를 품은 단일 HTML.
  클릭으로 접기/펼치기, 드래그·휠로 이동·확대, `/` 검색, 단계별 접기, 테마·레이아웃
  전환, SVG/PNG 내려받기
- `MM.toPresentation(spec)` — **발표를 요청받으면 이것.** 슬라이드가 아니라 맵 한 장을
  둔 채 카메라가 갈래를 하나씩 찾아간다(`←` `→` 이동 · `O` 전체 보기 · `F` 전체화면).
  정차하는 갈래만 밝고 나머지는 흐려지며, 상위 노드가 맥락으로 함께 담긴다
- `MM.toHTML(spec)` — 정적 단일 HTML. 저장하면 바로 열리고 인쇄도 된다
- `MM.render(spec)` — SVG 문자열. visualthink·explainer·webdoc 등 다른 HTML 산출물
  안에 그대로 넣을 수 있다
