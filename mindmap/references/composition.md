# Composition — 무엇을 트리로 만들고, 어디까지 담는가

## 마인드맵이 맞는 내용인가

마인드맵은 **하나의 중심에서 갈라져 나오는 내용**을 위한 형식이다.
갈라지지 않는 내용을 억지로 트리에 넣으면 읽는 사람이 없는 위계를 상상하게 된다.

| 내용의 모양 | 쓸 것 |
|---|---|
| 한 개념의 갈래, 한 주제의 하위 주제 | **이 스킬** |
| 순서·절차·인과 (A → B → C) | `visualthink` 의 `flow` / `steps` |
| 두세 입장의 대립 | `visualthink` 의 `compare` |
| 두 축으로 평가 | `visualthink` 의 `matrix` |
| 계층이지만 층마다 크기가 의미를 갖는 것 | `visualthink` 의 `pyramid` |
| 갈래가 4개 이하이고 각 갈래가 1단계뿐 | `visualthink` 의 `mindmap` 블록 |

**얕고 작은 마인드맵 하나만 필요하면 `visualthink` 를 쓴다.** 이 스킬은 깊이 3단계
이상이거나, 노드가 수십 개거나, 접었다 펴며 탐색해야 할 때를 위한 것이다.

## 레이아웃 고르기

| `layout` | 생김새 | 이럴 때 |
|---|---|---|
| `map` | 중심에서 좌우로 갈라짐 | **기본.** 갈래가 3~8개, 가로로 넓은 화면·슬라이드 |
| `right` | 왼쪽 루트에서 오른쪽으로만 | 갈래가 많거나(8+) 각 갈래가 깊을 때. 아웃라인·문서 세로 배치 |
| `down` | 위에서 아래로 (조직도) | 위계 자체가 메시지일 때. 분류 체계, 조직, 파일 트리 |

`map` 은 좌우 균형을 자동으로 맞춘다. 특정 갈래를 한쪽에 고정해야 하면 그 노드에만
`"side": "left"` 를 준다 — 전부 지정하면 균형 계산이 무의미해진다.

## 얼마나 담는가

**목표 개수를 먼저 정하고 내용을 맞추지 않는다.** 원본을 훑어 살아남아야 할 논점을
빠짐없이 세운 다음, 그 결과에 맞는 `density` 를 고른다(예산은 `spec.md`).

한 장에 벅찰 만큼 많으면 논점을 버리지 말고 이렇게 한다.

1. **층위를 올린다** — 형제 대여섯을 상위 갈래 하나로 묶는다. 마인드맵에서 가장
   자주 필요한 수정이다. 갈래가 12개면 그건 갈래가 아니라 목록이다.
2. **접어둔다** — 세부는 `"collapsed": true` 로 두고, 인터랙티브 출력으로 넘긴다.
   정적 한 장에서는 갯수 배지만 보이고, 클릭하면 펼쳐진다.
3. **맵을 나눈다** — 갈래 하나가 혼자 스무 노드면 그건 별도의 맵이다.

### 그래픽 요소는 신호일 때만

마인드맵이 밋밋해 보이는 이유는 보통 **장식이 없어서가 아니라 위계가 안 보여서**다.
장식을 얹기 전에 층위와 색부터 본다. 그다음 이 표를 쓴다.

| 이 맵이 하는 일 | 얹을 그래픽 |
|---|---|
| 개념·주제 정리 | 갈래에 `icon` 만. 나머지는 비운다 |
| 할 일·로드맵 | `status` + `progress`, 색은 상태에 맡기고 `legend` 를 붙인다 |
| 회고·평가 | `status`(good/bad 대신 색) + `emphasis` 로 결론 하나 |
| 리서치·레퍼런스 | `image` 썸네일 + `tags` |
| 이해관계·의존 | `links` 교차 연결선 두세 개 |

**한 맵에 두 가지까지.** 아이콘 + 상태까지는 읽히고, 거기에 진행률 + 태그 + 썸네일까지
겹치면 무엇을 봐야 할지 알 수 없게 된다.

### 모양의 신호

| 보이는 것 | 뜻하는 것 |
|---|---|
| 갈래 하나만 거대하고 나머지는 잎 하나씩 | 층위가 안 맞는다. 큰 갈래를 쪼개거나 나머지를 묶는다 |
| 모든 잎이 한 단어 | 트리가 필요 없는 내용일 수 있다. 목록이 더 정직하다 |
| 한 라벨에 쉼표로 여러 항목 | 층이 하나 빠졌다. 깊이를 아끼지 말고 아래로 내린다 |
| 한 노드에 아이 10명 | 중간 층을 하나 넣는다 |
| 라벨이 전부 문장 | 라벨은 명사구로. 설명은 `note` 로 |

## 흔한 실수

| 실수 | 대신 |
|---|---|
| 좌표·크기를 지정하려 함 | 불가능하다. 배치는 자동이다 |
| 잎마다 다른 색 | 색은 depth 1 갈래에만. 자식은 물려받는다 |
| 라벨에 문단을 넣음 | `note` 로 옮기고, 라벨은 명사구로 줄인다 |
| 모든 노드에 `mark` | 강조는 대비로 작동한다. 한 장에 한두 개 |
| 순서 있는 절차를 트리로 | 순서는 트리가 표현하지 못한다. `visualthink` 의 `steps` |
| `validate()` 생략 | 오류는 빈 화면이나 깨진 영역이 된다. 항상 검사한다 |
| 경고 났다고 캔버스를 키움 | 글자를 줄이거나 층위를 올린다 |
| 잎마다 아이콘 | 아이콘이 배경이 된다. 갈래에 먼저 붙인다 |
| 색은 자동인데 범례를 붙임 | 범례는 색에 뜻을 준 맵에만 |
| 교차 연결선 대여섯 개 | 두세 개까지. 그 이상은 트리가 아니라 그래프다 |
| 테마에 맞춰 스펙을 다시 씀 | 테마는 교체 가능하다. `theme` 만 바꾼다 |
