# explainer — 요약 + 펼침 상세 + 퀴즈 + 시각화 단일 HTML 생성

주어진 주제나 컨텍스트를 **자기완결형 단일 HTML 학습 문서**로 변환한다.
외부 JS 라이브러리 없음. 예외 둘: 폰트 CDN, 그리고 상세 설명에 mermaid 다이어그램을 쓸 때만 mermaid CDN.

> **로직·레이아웃·스타일은 이미 구현되어 있다.** `references/base-card.html` / `base-docs.html` /
> `base-steps.html`은 각각 **동작이 검증된 완성 파일**이다. HTML·CSS·JS를 처음부터 쓰지 않는다 —
> **복사한 뒤 파일 상단 `CONFIG` + `SECTIONS` + `VIZ` 블록만 교체**한다.
> 데이터 계약과 손대도 되는 범위는 `references/template.md`에 있다.

**다른 스킬과의 구분** — 암기가 목적이면 `flashcards`, 보고서·회의록·포스터면 `webdoc`,
발표 슬라이드면 `motion-slides`, 자동재생 연출이면 `mograph`. explainer는 **혼자 읽으며 이해하고
스스로 확인하는 학습 문서**다.

## 0. 템플릿 · 테마 결정

내용의 분량과 읽는 방식으로 판단한다. 애매하면 사용자에게 한 번만 묻는다.

| 템플릿 | 언제 | 구조 | 섹션 수 |
|---|---|---|---|
| **A. 카드 보드** `base-card.html` | 병렬적인 주제, 훑어보며 골라 읽기, 짧은 개념 묶음 | 히어로 → 툴바 → 카드 그리드(펼치면 전체 폭으로 확장) | 3~8 |
| **B. 강의노트** `base-docs.html` | 순서가 있는 긴 설명, 레퍼런스로 다시 찾아볼 문서 | 좌측 목차(스크롤스파이) + 우측 괘선 구획 본문 | 6~20 |
| **C. 스텝 롱폼** `base-steps.html` | 순서를 따라 읽어야 이해되는 내용, 절차·과정 설명 | 번호 원 + 연결선으로 순서를 표시하는 단일 컬럼 | 4~12 |

- 세 템플릿 모두 **세로 스크롤 한 방향**이다. 화면을 고정하는 요소(fixed 하단 바, sticky 툴바),
  단계 잠금, 진행률 추적은 의도적으로 넣지 않았다 — 하단이 가려지거나 클릭이 먹히는 문제의 원인이었다.
- 세 템플릿은 데이터 계약이 같다 — 나중에 "다른 형태로 보여줘"라고 하면 데이터 블록만 옮긴다.
- 템플릿을 고른 직후 **테마도 고른다**: `references/themes.md`의 6종 중 하나. 기본값(인디고)으로
  매번 수렴하지 말고 주제 톤에 맞춰 고르고 이유를 한 줄 남긴다.

## 1. 진행 절차

1. **소스 파악** — 입력(주제, 파일, 대화, URL 요약본)을 전부 읽고 **설명 단위**로 쪼갠다.
   - 섹션 1개 = 독자가 한 번에 소화할 개념 1개. "왜 필요한가 → 어떻게 동작하는가 → 무엇을 조심하는가 →
     실무에서 어떻게 하는가" 순서가 대부분의 주제에 맞는다.
   - 주제만 주어졌고 소스가 없으면 일반 지식으로 작성하되, **추정 수치·인용·사례를 만들지 않는다.**
     불확실한 부분은 문서에 넣지 않고 보고 단계에서 "다루지 못한 것"으로 알린다.
2. **구조 제안** — 제작 전 5~8줄로 짧게 제시한다:
   ```
   템플릿: B 강의노트 (순서가 있는 설명 + 나중에 찾아볼 레퍼런스)
   테마: E 틸 사이언스 (데이터·실험 중심 주제)
   섹션: 01 왜 필요한가 / 02 동작 원리 / 03 축출 정책 / 04 무효화 함정 / 05 체크리스트
   퀴즈: 섹션당 2~3문항 (객관식 중심, 표기 암기는 주관식)
   시각화: 02에 흐름 다이어그램, 03에 스텝 시뮬레이터
   ```
   사용자가 "바로 만들어줘" 톤이거나 섹션이 4개 이하로 명확하면 승인을 생략하고 진행한다
   (단 템플릿·테마 선택 자체는 생략 불가 — 내부적으로라도 결정하고 시작).
3. **제작 — base 파일 복사 후 데이터만 교체** (처음부터 쓰지 않는다):
   ```bash
   cp <스킬경로>/references/base-docs.html <작업디렉토리>/<주제-슬러그>-explainer.html
   ```
   그다음 파일 상단 `1. 설정 · 콘텐츠 · 시각화` 블록만 고친다 — `CONFIG` / `SECTIONS` / `VIZ`.
   필드 계약은 `references/template.md` §1~§4, 시각화 코드는 `references/viz-recipes.md`에서 복사한다.
   그 아래 엔진·부트 코드는 손대지 않는다.
4. **검증 (필수, 생략 금지)**:
   ```bash
   node <스킬경로>/references/check.js <생성한.html>
   ```
   제어문자·JS 문법·데이터 계약(id 중복, 퀴즈 answer 범위, viz 키, 요약 길이)·필수 마크업·
   mermaid CDN 정합성을 한 번에 본다. **FAIL 0이 될 때까지 다음으로 가지 않는다.**
   CSS를 고쳤거나 **새 시각화 위젯을 직접 만들었다면** agent-browser로 열어 데스크톱·모바일
   두 폭에서 확인한다 (`references/template.md` §7의 명령 그대로).
5. **보고** — 파일 경로, 템플릿·테마 선택 이유 한 줄, 섹션 수·퀴즈 문항 수·시각화 목록,
   그리고 **소스에서 확인되지 않아 넣지 않은 내용**을 알린다. WARN을 남겨 뒀다면 그 이유도.

## 2. 콘텐츠 3층 구조 — 이 형식의 핵심

한 섹션은 **요약(항상 보임) → 상세(펼침) → 퀴즈(펼침)** 세 층이고, 각 층의 역할이 겹치면 문서가 무너진다.

| 층 | 필드 | 역할 | 실패 신호 |
|---|---|---|---|
| 요약 | `summary` | **이것만 읽어도 요지가 남는다.** 결론부터, 2~3문장 | 배경 설명으로 시작해 결론이 없음 |
| 핵심 | `keys` | 요약을 스캔 가능한 2~4조각으로 분해 | 요약 문장을 그대로 잘라 붙임 |
| 상세 | `detail` | 근거·절차·표·코드·예외. 소제목 2~4개 | 요약을 길게 되풀이함 |
| 퀴즈 | `quiz` | 요약·상세를 읽었는지 확인. 섹션당 2~3문항 | 문서에 없는 지식을 물어봄 |

- **상세에서 처음 등장하는 개념이 없어야 한다.** 새 개념은 요약에 먼저 이름이 나와야 한다.
- 요약이 화면 한 덩어리를 넘기면 섹션을 쪼갠다.
- 퀴즈 해설(`why`)은 사실상 필수다 — 오답 화면이 학습의 절반이다.
- 표·코드·인용은 상세에만. 요약에 표가 들어가면 "먼저 보이는 것"이 무거워진다.
- 소스에 없는 사실을 만들지 않는다. 일반 상식으로 보충한 섹션은 보고에 명시한다.

## 3. 시각화 — 넣을 때와 넣지 말 때

시각화는 **장식이 아니라 이해의 대체 경로**다. 다음 중 하나에 해당할 때만 넣는다.

- 변수 하나가 결과를 비선형으로 바꾼다 (직접 움직여 봐야 감이 온다)
- 흐름·순서가 있고 "지금 어디"가 헷갈린다
- 규칙은 단순한데 반복하면 결과가 예상과 다르다
- 두 방식의 차이 자체가 설명이다
- 독자가 자기 숫자를 넣어 봐야 결론이 실감된다

레시피 8종(파라미터 슬라이더 · 흐름 다이어그램 · 스텝 시뮬레이터 · A/B 토글 · 인터랙티브 차트 ·
그리드 시뮬레이션 · 관계 그래프 · 계산기)은 `references/viz-recipes.md`에 **복사해 쓰는 코드**로 있다.
차트를 만들 때 **dataviz 스킬**이 사용 가능하면 형태·색 결정 전에 먼저 읽는다.

넣지 않는 경우: 단순 개념 나열, 이미 표로 충분한 비교, 조작할 변수가 없는 그림.
그런 내용은 mermaid 다이어그램(상세에 ```mermaid 코드블록)이나 표로 처리한다.
한 문서의 위젯은 **2~4개**가 적당하다. 모든 섹션에 위젯을 달면 어느 것도 눈에 띄지 않는다.

## 4. base 파일이 이미 보장하는 것 (다시 만들지 않는다)

- **요약 먼저 구조**: 요약·핵심 박스는 항상 노출, 상세·시각화·퀴즈는 버튼으로 펼침(`hidden` 토글 + 짧은 페이드, `aria-expanded`).
- **퀴즈 4종**: 객관식·복수선택·주관식(대소문자·공백·문장부호 무시)·OX. 즉시 채점, 정답/오답 표시,
  해설, 다시 풀기.
- **시각화 슬롯**: 첫 열람 시 지연 마운트, 실패 시 폴백 메시지, 테마 변경 시 재렌더 이벤트(`ex:theme`).
- **markdown 렌더링**: 소제목·굵게(포인트색)·코드·코드블록·표·인용/경고 콜아웃·목록(1단 중첩)·
  링크·이미지·하이라이트·mermaid. (지원 범위는 `template.md` §5)
- **탐색**: 섹션 검색(`/`), 전체 펼치기(`E`), 테마 순환(`T`, auto→dark→light), 해시 딥링크(`#섹션id`),
  B는 스크롤스파이 목차.
- **상태를 저장하지 않는다**: localStorage를 쓰지 않고 진행률·완료 표시도 없다. 새로 고치면 초기 상태다.
  퀴즈는 그 자리에서 채점·해설만 보여준다(다시 풀기 버튼 제공).
- **접근성·인쇄·반응형**: 다크 모드(OS + 수동), `prefers-reduced-motion`, `focus-visible`,
  한국어 `word-break:keep-all`, 인쇄 시 전체 펼침 + 흑백 팔레트, 모바일 단일 컬럼(B는 목차가 본문 위로 쌓인다).

## 5. 산출물 위치

작업 디렉토리에 `<주제-슬러그>-explainer.html`로 저장한다(base 파일을 이 경로로 복사).
사용자가 경로·파일명을 지정하면 그에 따른다. 한국어 파일명도 허용한다.

## 6. 참고 파일

|---|---|

| `references/viz-recipes.md` | 시각화 위젯 8종 복사용 코드 + 선택 기준 |
