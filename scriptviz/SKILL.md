# scriptviz

영상 대본의 **진행**을 축으로, 비트마다 화면에 띄울 시각화를 만든다.
**JSON만 쓰면 배치·타이밍·전환은 엔진이 계산한다.** 좌표를 지정할 수 없고,
지정할 필요도 없다.

## 이 스킬인가, 다른 스킬인가

| 상황 | 쓸 것 |
|---|---|
| 낭독 대본이 있고 그 진행에 맞춰 화면이 넘어가야 함 | **이 스킬** |
| 사람이 앞에서 말하는 발표 자료 | `motion-slides` (손으로 짜는 슬라이드) |
| **이 덱을 발표에도 쓰고 싶다** | 이 스킬의 `--present` — 같은 스펙에서 발표용 HTML |
| 자동 재생되는 모션그래픽·인트로·키네틱 타이포 | `mograph` |
| 대본 자체를 써야 함 | `youtube-script` — **출력 모드 C(화면 대본 `.sv.md`)로 받으면 그대로 읽힌다** |
| 다이어그램 한 장 | `visualthink` · `mindmap` (낸 SVG를 `split` 장면에 넣는다) |

## 워크플로

0. **대본을 먼저 읽는다. 그다음 용도와 톤을 확인한다.**

   장면을 고르려면 대본이 무슨 모양인지 알아야 한다. 먼저 통독하고,
   **비트 경계와 장면 타입을 정한 뒤에** 스펙을 쓰기 시작한다.

   **사용자가 이미 말했다면 묻지 않는다.** "쇼츠로", "다큐 톤으로", "녹화해서
   편집기에 넣을 거야" 같은 단서가 있으면 그대로 따른다. 단서가 없을 때만
   `AskUserQuestion` 으로 **한 번에 두 질문**을 묻는다.

   | 질문 | 선택지 |
   |---|---|
   | 어떻게 쓸 건가요? | **화면 녹화**(전체화면으로 틀고 녹화) · **컷 내보내기**(PNG 시퀀스를 편집기에) · **오버레이**(크로마키로 영상 위에 합성) |
   | 화면비와 톤은? | **16:9**(midnight·paper·warm) · **9:16 쇼츠**(neon) |

   테마 고르는 기준은 `references/theming.md`. **분량은 묻지 않는다** — 비트 수는
   대본이 정한다.

1. **필요한 레퍼런스만 읽는다.** 기억으로 JSON을 쓰지 않는다. 네 개로 나뉘어 있으니
   판단에 필요한 것만 연다.

   | 파일 | 언제 |
   |---|---|
   | `references/direction.md` | 대본을 어디서 자를지, 어떤 장면을 붙일지, 리듬과 타이밍, 강조 이펙트를 어디에 쓸지 |
   | `references/scenes.md` | 장면 19종의 필드와 JSON, 스텝 수, 픽토그램 191종 이름과 `iconStyle`, 강조 이펙트 `fx` |
   | `references/theming.md` | 테마 4종, 배경 레이어·장식·등장 연출, 16:9/9:16, 크로마키·안전영역 |

   보통은 `direction.md` 로 비트를 짜고 `scenes.md` 로 스펙을 쓰면 끝난다.
   `api.md` 는 584줄이라 통째로 열지 않는다 — **필요한 절만 연다.**

   | 지금 하는 일 | `api.md` 의 절 |
   |---|---|
   | 대본 `.md` 문법, 이미지 섞어 쓰기 | `#대본-문법-fromscript` |
   | 녹음 자막으로 타이밍 확정 | `#자막으로-타이밍-확정하기` |
   | mp3 얹기, 폰·iOS 사정 | `#음성mp3과-함께-재생하기` |
   | PNG 시퀀스·WebM 뽑기 | `#컷-내보내기--영상-녹화` |
   | 조작키를 사용자에게 알려줄 때 | `#조작키` |
   | 발표용으로도 뽑을 때 | `#발표용으로-뽑기---present` |

1.5. **쓸 이미지가 있으면 먼저 훑는다.**

   ```bash
   node <skill>/assets/sv.js images shots/
   ```
   파일마다 크기·비율·놓을 자리를 알려준다. 그런데 **이 목록은 어디에 놓을지만 정해준다.**

   > **무엇이 찍혔는지는 직접 열어 봐야 한다.** 파일명만 보고 캡션을 지어내면 없는
   > 사실을 쓰게 된다 — `office.jpg` 가 사무실 사진이라는 보장은 없다. 이미지를 열어
   > 확인한 것만 캡션을 달고, 확인 못 한 것은 캡션 없이 쓰거나 빼놓는다.

   훑은 뒤 **대본 안에 자리를 표시한다** — 나중에 JSON 에서 비트 번호를 세는 것보다
   정확하다.

   ```markdown
   ![2026년 3월, 마지막 사무실](shots/office.jpg)
   처음엔 책상 네 개였다. 여기서 전부 시작했다.
   ```
   `@split ![](경로)` 로 쓰면 왼쪽은 말, 오른쪽은 사진이 된다.
   문법은 `references/api.md#대본과-이미지를-섞어-쓰기`,
   배치 기준은 `references/direction.md#이미지를-어디에-놓나`.

2. **대본이 글로 있으면 초안부터 뽑는다.**

   ```bash
   node <skill>/assets/sv.js script.md --json > draft.json
   ```

   **자막 파일(SRT·VTT)만 있으면** 그것으로 초안을 만든다. 이때는 타이밍이 처음부터
   실측이다. `node <skill>/assets/sv.js voice.srt --json > draft.json`

   `fromScript` 가 문단을 비트로 끊고 낭독 시간을 계산해준다. **자동으로 고른 장면
   타입은 초안이지 결론이 아니다** — `direction.md` 의 표로 하나씩 다시 고른다.
   대본이 없거나 짧으면 `assets/examples/starter-deck.json`(16:9 8비트) ·
   `starter-shorts.json`(9:16)을 열어 갈아끼우는 편이 빠르다.

   초안을 뽑은 뒤에는 **아트디렉션 스타일 프레임부터 비교한다.** 추상적인 톤 질문 대신
   오프닝·대표 데이터·결론을 세 방향으로 실제 렌더링해 고른다.

   ```bash
   node <skill>/assets/sv.js draft.json deck.html --direct --style-frames
   # deck.styles.html 에 세 아트디렉션 × 대표 비트가 나온다
   ```

   선택한 방향은 `artDirection`으로 고정한다. `--direct`가 `composition`·감정 곡선 `arc`·
   모티프 상태·이미지 처리 프리셋을 배정하지만, **문장의 의미에 맞는 장면 타입은 바꾸지 않는다.**

3. **비트 표를 만들어 사용자에게 보여준다.** 규모가 크면 확인을 받고 진행한다.

   | # | 낭독 요지 | 초 | 장면 | 이미지 |
   |---|---|---|---|---|
   | 3 | 첫 달 이탈률 41% | 7.2 | `pictograph` (100명 중 41) | — |
   | 4 | 처음 사무실 | 6.0 | `split` | `shots/office.jpg` (열어봄: 책상 넷) |

   여기서 리듬을 점검한다 — 같은 장면 3연속, `stat` 남발, 무거운 비트 연속,
   그리고 **글자만 있는 장면이 몇 개나 이어지는지.** 셋 이상 이어지면 그중 하나를
   그림 장면(`pictograph`·`donut`·`line`·`funnel`·`matrix`·`cards`)으로 바꾼다.

   `split` 의 오른쪽에 그림을 넣을 때는 **`flow`·`picto`·`stat`·`items`·`quote` 를 먼저
   본다.** `svg`·`html` 로 손수 짜면 크기·선굵기를 스킬이 보증하지 못한다
   (`references/scenes.md#split--왼쪽-말-오른쪽-그림`).

   이 표를 건너뛰어도 `validate` 가 대신 잡는다 — 글자 수·항목 수 상한(화면비별),
   같은 장면 3연속, 글자만 있는 장면 3연속, 정보량 대비 체류시간, 픽토그램 이름까지
   **60가지 넘게 기계로 확인한다.** 반대로 기계가 못 보는 건 하나다 — **문장이 좋은가.**
   장면 제목이 라벨("시장 현황")인지 결론("시장은 3년째 축소 중")인지는 사람·모델이
   판단해야 한다 (`direction.md` 의 표).

4. **스펙을 쓰고 반드시 검증한다.**

   ```js
   const SV = require('<skill>/assets/scriptviz.js');
   const check = SV.validate(spec);
   if (!check.ok) { /* check.errors 를 보고 고친다 */ }
   if (check.warnings.length) console.warn(check.warnings);   // 길이·개수·리듬·총 시간
   fs.writeFileSync('deck.html', SV.toHTML(spec));
   ```

   한 줄로 끝내려면: `node <skill>/assets/sv.js deck.json deck.html --theme midnight`
   (`deck.timing.csv` 도 같이 나온다.)

5. **녹음이 끝났으면 자막으로 타이밍을 확정하고, 음성을 얹는다.**

   ```bash
   node <skill>/assets/sv.js deck.json deck.html --subs voice.srt --audio voice.mp3
   ```

   추정은 비트가 쌓일수록 어긋난다 — 8분 대본에서 마지막 비트가 2분 넘게 밀리는 일이
   실제로 있다. 자막을 넣으면 `at`·`sec` 이 실측으로 박히고 프롬프터의 노래방 표시가
   목소리와 맞는다. 화면 구성은 그대로고 시각만 바뀐다.

   **자막이 먼저, 음성이 그다음이다.** `--audio` 만 붙이면 전환은 여전히 글자 수 추정이라
   목소리와 어긋나고 `validate` 가 경고한다. 둘 다 붙이면 mp3 가 HTML 안에 들어가 시계를
   잡고 화면이 따라간다.

   자막과 안 맞는 비트는 추정을 그대로 두고 건너뛴 이유를 알려준다 — 전부 건너뛰면
   자막 짝이 틀린 것이다. 동작·옵션·폰/iOS 사정은 `references/api.md`.

   mp3 와 대본으로 자막을 만드는 것은 이 스킬의 일이 아니다(강제 정렬 도구를 쓴다).
   이 스킬은 **만들어진 자막으로 타이밍을 박고, mp3 를 그 위에 얹어 함께 튼다.**

6. **결과를 눈으로 확인한다.** 시각 산출물이라 빌드 성공만으로는 부족하다.
   agent-browser 로 열어 **비트마다** 스크린샷을 찍고 넘침·겹침·안전영역을 본다.

   ```bash
   node <skill>/assets/shots.js deck.html /tmp/shots --beat --wait 1200
   ```

   agent-browser를 쓸 수 없으면 확인하지 못했다고 말하고 넘긴다 — 안 본 것을 본 것처럼
   넘기지 않는다.

7. **넘길 때 함께 말해준다.** 늘 말할 것 — 녹화 절차(`C` → `F` → 재생), 타이밍 시트
   자리, PNG 시퀀스 명령. 조작키는 페이지 안에서 `?` 로도 본다. 해당할 때만 덧붙인다:

   | 언제 | 말해줄 것 |
   |---|---|
   | 음성을 붙였다 | 소리는 한 번 눌러야 시작(자동 재생이면 시작판) · `M` 음소거 · **WebM 에는 소리가 안 담겨** `ffmpeg` 로 원본 mp3 를 얹어야 한다 |
   | 자막이 없다 | 프롬프터 노래방 표시가 **글자 수 추정 위치**다 — 읽어 보고 앞서가면 `cps` 를 낮춘다. 녹음이 나오면 `--subs` 로 실측으로 바꾼다 |
   | 폰으로 본다 | 쇼츠가 아니면 **눕혀서** (세로에서 16:9 는 폭에 갇힌다) · iOS 에서 소리 시각이 안 흐르면 `--no-inline-audio` 로 다시 뽑는다 |

## 기억할 것

- **화면은 낭독문의 요약이지 낭독문이 아니다.** 말과 같은 문장을 띄우면 둘 다 안 읽힌다.
  `say` 는 타이밍과 프롬프터용이고 화면에 나가지 않는다.
- **장면은 문장의 모양이 정한다.** 전부 `hero` 로 만드는 것이 가장 흔한 실패다.
- **같은 숫자도 그리는 방법이 여럿이다.** "41%"는 `stat`(읽는다) · `pictograph`(세어 본다) ·
  `donut`(전체 중 얼마) · `bars`(견준다) 중 어디에 담느냐로 전달력이 갈린다.
  화면이 밋밋하면 글자를 키우지 말고 **장면 타입을 바꾼다.**
- **아이콘은 장식이 아니라 라벨이다.** 그 항목이 무엇인지 말해주는 것만 붙인다.
  `cards` 는 아이콘이 있어야 `list` 와 구분된다. `"icon": "돈"` 처럼 한글로도 부른다.
- **비율은 `pictograph` 로.** 기본(전체 중 얼마) · `groups`(100명이 어디로 갔나) ·
  `rows`(두 시점 비교) 세 가지가 있고, 소수를 주면 마지막 칸이 반만 찬다.
  퍼센트를 말로 하는 것보다 세어 보게 하는 편이 늘 세다.
- **배경 레이어(`bg`)는 덱 전체에 하나.** 강조할 한두 장면만 다르게 준다.
- **한 비트 8~15초, 스텝 3~4개.** 25초가 넘으면 쪼갠다. 3초 미만도 남발하지 않는다.
- **숫자에는 출처를 붙인다**(`caption`). 영상은 캡처돼 돌아다닌다.
- **`raw` 는 탈출구다.** 전체의 4분의 1을 넘으면 설계를 다시 본다.
- **타이밍 추정은 추정이다.** 녹음이 끝났으면 자막을 만들어 `--subs` 로 실측으로 바꾼다.
  자막이 없으면 `at`(절대 타임코드)으로 맞추거나 수동으로 넘긴다.
- **음성(`--audio`)은 자막 다음이다.** 소리는 실측인데 화면이 추정이면 어긋나는 것이
  더 잘 보인다. 붙이면 mp3 가 시계를 잡고 화면이 따라간다.
- 9:16은 16:9 분량이 그대로 들어가지 않는다. 항목과 글자 수를 줄인다.
- 다른 스킬이 만든 SVG(`visualthink`·`mindmap`)는 `split` 장면의 `right.svg` 에 그대로 넣는다.

## 산출물

- **`deck.html`** — 플레이어가 들어 있는 단일 파일. **음성을 붙였으면 mp3 까지 이 안에 있다**
  (재생하면 목소리가 흐르고 화면이 그 목소리를 따라간다 · `M` 음소거). 자동 재생(`P`)과 수동 전환(`Space`),
  **노래방식 프롬프터**(지금 읽을 어절까지 칠해진다 — 자막을 넣었으면 실측 위치 ·
  `L` 로 대본 위치만 흐르게),
  안전영역 가이드(`G`), 크로마키(`X`), 클린 모드(`C`).
  차트는 열릴 때 그려지고(도넛 조각, 꺾은선 획, 막대, 카운트업, 아이소타입 점등)
  정지 화면으로 뽑아도 완성된 상태로 잡힌다
- **`deck.timing.csv`** — 비트별 시작·끝·길이·낭독문. 편집기 타임라인용
- **PNG 시퀀스 / WebM** — `shots.js` 로. 1920×1080, 파일명이 곧 순서
