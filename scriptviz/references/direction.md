# Direction — 대본을 비트로 쪼개고 장면을 고르는 법

## 비트는 문단이 아니라 **말의 단위**다

한 비트는 "화면이 바뀌어야 할 만큼 말이 넘어간 지점"까지다. 기준은 세 가지다.

1. **주장이 바뀌면 자른다.** 같은 주장을 부연하는 문장은 같은 비트에 둔다.
2. **8~15초를 넘기면 자른다.** 한 그림이 15초 넘게 그대로면 시청자는 화면을 떠난다.
   25초가 넘으면 `validate()` 가 경고한다.
3. **숫자·인용·목록이 나오면 자른다.** 그건 그 자체로 화면을 요구하는 재료다.

거꾸로, **3초 미만짜리 비트를 남발하지 않는다.** 화면이 말보다 빨리 바뀌면
시청자는 그림을 못 읽는다. 짧은 문장 두셋은 한 비트에 묶고 스텝으로 나눈다.

## 장면 고르기

대본 문장의 **모양**이 장면을 정한다. 감으로 고르지 않는다.

| 대본이 이렇게 말하면 | 장면 |
|---|---|
| "…입니다" 하고 못 박는 한 문장 | `hero` |
| 숫자 하나를 크게 말한다 | `stat` |
| **비율**을 말한다 ("열 명 중 넷") | `pictograph` — 퍼센트보다 훨씬 세게 박힌다 |
| **구성비**를 말한다 ("절반이 구독에서") | `donut` |
| **시간에 따른 변화**를 말한다 | `line` |
| 항목별 크기를 비교한다 | `bars` |
| **단계마다 줄어든다** ("방문 → 가입 → 결제") | `funnel` |
| "이유는 세 가지", "첫째… 둘째…" | `list`, 아이콘을 붙이면 `cards` |
| 병렬 개념 3~4개를 소개한다 | `cards` |
| "반면", "대신", "A는 …지만 B는 …" | `compare` |
| **두 기준으로 나눈다** ("비용과 효과로 보면") | `matrix` |
| "먼저 … 그다음 … 마지막으로" (순서) | `flow` |
| 연도·시점이 두 개 이상 | `timeline` |
| 남의 말을 옮긴다 | `quote` |
| 실물·화면을 보여줘야 한다 | `image` |
| 말과 그림이 동시에 필요하다 | `split` |
| 사람 이름·소속을 띄운다 | `lower` |
| 챕터가 바뀐다 | `title` |

**전부 `hero` 로 만드는 것이 가장 흔한 실패다.** 자막이 커진 것일 뿐 시각화가 아니다.
`fromScript()` 가 자동으로 고른 타입은 초안이다 — 반드시 다시 본다.

### 같은 숫자라도 그림이 다르다

"41%"는 네 가지로 그릴 수 있고, 셋은 그림이고 하나는 글자다.

| 장면 | 읽히는 방식 | 쓸 자리 |
|---|---|---|
| `stat` | 숫자를 읽는다 | 수치 자체가 주인공일 때. 덱당 1~3번 |
| `pictograph` | **세어 본다** | "열 명 중 넷"처럼 사람 수로 와닿아야 할 때 |
| `pictograph` + `groups` | 100명이 어디로 갔는지 본다 | 구성비를 사람 수로 말할 때 |
| `pictograph` + `rows` | 두 시점을 나란히 견준다 | "2022엔 22%, 2024엔 41%" |
| `donut` | 전체 중 얼마인지 본다 | 나머지가 무엇인지도 중요할 때 |
| `bars` | 항목끼리 견준다 | 여러 항목의 크기 차이가 논점일 때 |

**그림이 부족하다고 느껴지면 숫자 장면을 바꿔 보는 것이 가장 빠르다.**
글자 크기를 키우는 것으로는 해결되지 않는다.

## 리듬

덱 전체를 표로 늘어놓고 본다. 비트 번호, 낭독 시간, 장면 타입, 스텝 수.

- **같은 장면 타입 3연속 금지.** `validate()` 가 경고한다. 가운데 비트를 위 표에 다시 통과시킨다.
- **`stat` 은 덱당 1~3번.** 매번 숫자가 크면 어떤 숫자도 크지 않다.
- **글자만 있는 장면(`hero`·`quote`·`list`·`title`·`raw`)이 3연속이면 하나를 그림 장면으로
  바꾼다.** 아이콘이 하나라도 붙어 있으면 글자만인 장면으로 세지 않는다.
  **`validate` 가 잡아준다** — 워크플로를 건너뛰어도 새어나가지 않는다.
- **정보량에 비해 머무는 시간이 짧으면 안 된다.** 스텝 4개 이상인 장면은 대략
  `0.8 + 스텝수 × 0.45`초는 필요하다. 모자라면 `sec` 를 늘리거나 장면을 나눈다.
  이것도 `validate` 가 잡는다.
  `cards`·`donut`·`line`·`pictograph`·`funnel`·`matrix` 중 내용에 맞는 것으로.
- **그래픽 장면도 연속 2개까지.** 차트가 계속 나오면 데이터 대시보드지 영상이 아니다.
  무거운 차트 다음에는 `hero` 한 줄로 숨을 돌린다.
- **무거운 비트(스텝 4개 이상) 다음엔 가벼운 비트**(스텝 1개짜리 `hero`)를 둔다.
- **첫 비트는 `title`, 마지막 비트는 결론 한 문장의 `hero`.**
- 화면이 바뀌지 않아야 할 구간(진행자가 카메라를 보고 길게 말하는 곳)은
  비트를 나누지 말고 하나로 길게 둔다. 억지로 그림을 넣지 않는다.

## 타이밍

낭독 시간은 **대본 글자 수에서 자동으로 계산**된다(공백 제외 초당 5.0자 + 문장 끝 0.35초).
말이 빠르거나 느리면 `spec.cps` 로 조정한다 — 실제 녹음 1분을 재서 글자 수를 나누면 자기 값이 나온다.

| 손댈 곳 | 언제 |
|---|---|
| `beat.sec` | 그 비트만 시간을 못 박을 때 |
| `beat.at` | 이미 녹음된 오디오가 있고 타임코드를 아는 경우 (다음 `at` 까지가 그 비트의 길이) |
| `scene.stepAt` | 스텝이 특정 단어에서 터져야 할 때 (`[0, 1.4, 3.0]` 또는 비율 `[0, 0.3, 0.7]`) |
| `spec.cps` | 덱 전체 속도 |

`targetSec` 을 적어두면 추정 길이가 목표에서 20% 이상 벗어날 때 경고한다.

**추정은 추정이다.** 녹음본이 있으면 그걸로 맞추는 게 항상 낫다 — `at` 을 쓰거나,
수동 모드로 넘기면서 녹화한다.

이 추정은 프롬프터의 **노래방식 진행 표시**에도 그대로 쓰인다. 어절마다 글자 수로
시간을 나눠 칠하므로, `cps` 가 실제 낭독 속도와 맞을수록 위치도 맞는다.
**한 번은 실제로 읽어 보며 확인한다** — 표시가 앞서가면 `cps` 를 낮추고, 뒤처지면 올린다.

## 흔한 실수

| 실수 | 대신 |
|---|---|
| 낭독문을 화면에 그대로 띄움 | 화면은 요약이다. 말과 글자가 겹치면 둘 다 안 읽힌다 |
| 한 비트에 스텝 6개 | 비트를 쪼갠다. 스텝은 3~4개까지 |
| 모든 비트에 그림 | 말만 흐르는 구간이 있어야 그림이 산다 |
| 장면 제목이 라벨 ("시장 현황") | 결론으로 쓴다 ("시장은 3년째 축소 중") |
| 숫자에 출처가 없음 | `caption` 에 출처를 적는다. 영상은 캡처돼 돌아다닌다 |
| 9:16에 16:9 분량을 그대로 | 세로는 한 화면에 절반만 들어간다. 항목·글자 수를 줄인다 |
| 배경 레이어를 매 장면 바꿈 | 배경은 공기다. 덱 전체에 하나, 강조할 한두 장면만 다르게 |
| 아이콘을 장식으로 뿌림 | 아이콘은 그 항목이 무엇인지 말해야 한다. 애매하면 빼는 게 낫다 |
| 한 장면에 아이콘 스타일 여러 개 | `iconStyle` 은 덱 전체에 하나로 통일한다 |
| 아이소타입에 아이콘 200개 | 100개까지. 그 이상은 세는 그림이 아니라 무늬다 |
| 도넛에 조각 8개 | 5개까지. 나머지는 "기타"로 묶는다 |
| 안전영역 밖에 글자 | `G` 로 가이드를 켜고 확인한다 (바깥 5% 밖으로 넘기지 않는다) |
| 타이밍을 눈대중으로 | `.timing.csv` 를 편집기에 그대로 넣는다 |

## 강조 이펙트를 어디에 쓰나

`fx` 는 **영상 전체에서 한두 번**이다. 매 비트에 터지면 아무 비트도 안 세진다.
쓸 자리는 대개 셋뿐이다.

- **핵심 수치가 확정되는 비트** — `impact` (숫자가 꽂히는 소리를 그림으로)
- **반전·전환점** — `ripple` 이나 `burst`
- **마지막 결론** — `confetti` 나 `sparkle`

쓰지 말아야 할 자리:

- 연속한 두 비트 (둘 다 죽는다)
- 글자가 많은 비트 (읽는 걸 방해한다)
- 이미 움직임이 큰 장면 — `pictograph` 채워지기, `bars` 자라기, `donut` 그려지기.
  장면 자체가 연출이라 이펙트를 얹으면 지저분해진다. 정 쓰겠으면 `step` 을 뒤로 미뤄
  장면 애니메이션이 끝난 뒤에 터뜨린다.

**낭독과 어긋나지 않게.** 이펙트는 비트(또는 스텝) 진입에 붙는다. "이 단어에서
터졌으면" 싶으면 그 단어가 있는 지점에 스텝을 하나 만들고 `fx.step` 을 거기 맞춘다.

## 이미지를 어디에 놓나

`node <skill>/assets/sv.js images <폴더>` 로 재료를 먼저 훑는다. 비율이 자리를 정한다.

| 비율 | 자리 | 왜 |
|---|---|---|
| 가로 1.5 이상 | `image` (화면 전체) | 무대가 16:9 라 잘림 없이 채워진다 |
| 정사각·세로 | `split` 의 `right.src` | 전체로 쓰면 좌우가 크게 잘린다 |
| 글자가 많은 스크린샷 | `image` + `"fit": "contain"` | `cover` 로 채우면 글자가 잘려 못 읽는다 |
| SVG 도해 | `split` 의 `right.svg` | `references/scenes.md#split--왼쪽-말-오른쪽-그림` 의 주의를 읽는다 |

**얼마나 자주 쓰나**

- 사진이 연속 세 장을 넘으면 슬라이드쇼가 된다. 사이에 글자·데이터 장면을 끼운다.
- 반대로 **글자만 있는 장면이 3연속이면** 사진 한 장이 숨통을 틔운다(`validate` 가 잡는다).
- 같은 사진을 두 번 쓰지 않는다. 다시 보여줄 일이면 그 대목을 한 비트로 합친다.

**캡션**

- 캡션은 사진이 말하지 못하는 것만 쓴다 — 언제·어디서·누가. 보이는 걸 다시 쓰지 않는다.
  ("사무실 사진" ❌ → "2026년 3월, 마지막 사무실" ✅)
- **열어 보지 않은 사진에는 캡션을 달지 않는다.** 파일명은 근거가 아니다.
- `kenburns` 는 기본 켜짐이다. 정지 화면이 필요하면(스크린샷·도표) `false` 로 끈다.

**크기**

화면은 1920 폭이면 충분하다. 큰 원본을 그대로 넣으면 HTML 이 몇 MB 가 되고,
그만큼 브라우저가 느려진다. `images` 명령이 900KB 넘는 파일을 짚어준다.
