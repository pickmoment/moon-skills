# Theming — 테마·화면비·합성

## 테마 4종

| 테마 | 톤 | 어울리는 영상 |
|---|---|---|
| `midnight` | 짙은 남색 + 시안/핑크 | **기본.** 정보·분석·리뷰. 대부분의 유튜브 화면 |
| `paper` | 밝은 종이 + 먹색, 표제는 명조 | 다큐·역사·에세이. 자료 화면이 많이 섞일 때 |
| `neon` | 검정 + 형광 연두/마젠타 | 빠른 컷, 쇼츠, 하이에너지 |
| `warm` | 따뜻한 갈색 + 주황 | 인터뷰·회고·브랜드 |

테마는 스펙을 바꾸지 않는다 — `theme` 만 바꾼다. 색은 CSS 변수로 나가 있어서
`raw` 장면에서도 `var(--accent)` 로 그대로 쓸 수 있다.

| 변수 | |
|---|---|
| `--bg` `--bg2` | 배경, 그라디언트 두 번째 색 |
| `--ink` `--muted` | 본문, 보조 텍스트 |
| `--accent` `--accent2` | 강조 두 종 |
| `--panel` `--line` | 카드 바탕, 테두리 |
| `--fs-hero` `--fs-stat` … | 타입 스케일 (`scenes.md` 참조) |

## 아트디렉션 팩 6종

`theme`이 색상 스킨이라면 `artDirection`은 색·서체·밀도·기하·표면·이미지 처리·모션·
반복 모티프를 함께 고정한다. 새 덱은 테마보다 아트디렉션을 먼저 고른다.

| 값 | 시각 문법 |
|---|---|
| `editorial-documentary` | 명조 표제, 열린 표면, 비대칭 편집, 흑백 사진 |
| `broadcast-data` | 선명한 축과 정렬, 정밀한 데이터 그래픽 |
| `kinetic-brutalist` | 거대 활자, 각진 색면, 하드한 대비 |
| `cinematic-minimal` | 넓은 여백, 낮은 채도, 느린 오브 모티프 |
| `soft-explainer` | 둥근 표면, 부드러운 대비, 점 모티프 |
| `tech-interface` | 조밀한 격자, 가는 선, 인터페이스형 리듬 |

```jsonc
{ "artDirection": "editorial-documentary",
  "beats": [{ "say": "시작합니다.", "scene": { "type": "hero", "text": "시작합니다" } }] }
```

CLI의 `--direct`는 팩을 고른 뒤 장면별 구도, `setup → tension → evidence → turn → resolution`
감정 곡선, 모티프 상태를 배정한다. `--style-frames`는 오프닝·대표 데이터·결론을 세 가지
팩으로 나란히 보여주는 `.styles.html`을 함께 만든다.

## 화면비

| `aspect` | 캔버스 | |
|---|---|---|
| `16:9` | 1920×1080 | 기본 |
| `9:16` | 1080×1920 | 쇼츠·릴스. 열은 세로로 쌓이고 타임라인 축이 세로가 된다 |

같은 스펙으로 둘 다 뽑을 수 있지만 **분량은 그대로 옮겨지지 않는다.**
세로는 한 화면에 들어가는 항목이 절반이다 — `validate()` 가 화면비에 맞춰
글자 수·항목 수를 검사하니 경고를 따른다.

## 화면 밖은 무대가 아니다

무대는 고정 캔버스이고 뷰포트에는 `scale`로 맞춰진다. 창 크기가 달라져도
줄바꿈·여백·자간이 그대로라, **어떤 화면에서 녹화해도 같은 그림이 나온다.**
무대 바깥은 검정으로 남으니 창을 정확히 16:9로 맞출 필요가 없다.

## 배경 레이어

`spec.bg` 로 덱 전체에, `beat.bg` · `scene.bg` 로 장면 하나에만 줄 수 있다.
**배경은 정보가 아니라 공기다** — 글자를 방해하기 시작하면 이미 과한 것이다.

| `bg` | 생김새 | 어울리는 자리 |
|---|---|---|
| `plain` | 기본 그라디언트만 | 기본값 |
| `grid` | 옅은 격자 (가운데로 갈수록 사라짐) | 데이터·분석 장면 |
| `dots` | 점 패턴 | 목록·카드 |
| `blob` | 큰 색 얼룩 두 개가 아주 느리게 흐른다 | 타이틀·결론처럼 감정이 실리는 장면 |
| `mesh` | 얼룩 세 개, 더 화려하다 | 오프닝 |
| `rays` | 대각선 광선 | 강조 한 장면 |
| `scan` | 가로 스캔라인 | `neon` 테마, 테크 소재 |
| `noise` | 미세한 노이즈 그레인 | `paper` 테마, 다큐 |

`blob` · `mesh` 는 34초 주기로 아주 느리게 움직인다. 정지 화면으로 뽑아도 문제없다.

## 장식

| | |
|---|---|
| `scene.watermark: "03"` | 무대 뒤 오른쪽 아래에 깔리는 큰 윤곽 글자. 챕터 번호나 한 단어 |
| `spec.frame: "corners"` | 네 모서리 브래킷. 덱 전체에 일관된 프레임감을 준다 |
| `spec.progress: true` | 화면 맨 아래 얇은 진행 바 (녹화 화면에 남는다 — 필요할 때만) |

셋 다 **한 덱에 하나만** 고른다. 워터마크와 코너 브래킷과 진행 바를 다 켜면
화면이 시끄러워진다.

## 등장 연출

`scene.reveal` 로 요소가 나타나는 방식을 바꾼다 — `up`(기본) `fade` `pop` `left`
`wipe` `blur`. `title` · `hero` 는 기본이 **단어 단위 스태거**이고, 한꺼번에
띄우려면 `stagger: false`.

비트 사이의 전환은 `transition` 이다(`fade` `up` `wipe` `cut` `morph`). `morph`는 같은
`share` 이름을 FLIP으로 잇고, 공유 요소가 없으면 페이드한다. `transition` 은 장면과
장면 사이, `reveal` 은 장면 안의 요소들이다.

## 합성용

- **`X` 키 / `--chroma <color>`** — 배경을 단색 키 컬러로 바꾼다(기본 `#00B140`).
  그라디언트와 비네트가 함께 꺼져서 키가 깨끗하게 빠진다. `lower` 장면과 함께 쓰면
  이름표만 뽑아 영상 위에 얹을 수 있다.
- **`G` 키** — 안전영역 가이드(바깥 5% 파랑, 10% 분홍)와 중앙 십자.
  자막·로고가 들어갈 자리를 피해 글자를 배치할 때 켠다.
- **`C` 키** — UI를 전부 숨긴다. 녹화 전에 반드시 누른다(`--clean` 으로 처음부터 숨길 수도 있다).

## 화면 자막 모양

자막을 넣은 덱에만 나온다(`references/api.md#화면-자막`).

| | 16:9 | 9:16 |
|---|---|---|
| 글자 크기 | 38px | 46px |
| 아래 여백 | 6.2% | 11% |
| 최대 폭 | 78% | 86% |

기본은 반투명 검정 박스(`#080a10` · 투명도 0.72) 위 흰 글자다. **밝은 테마에서도
박스는 어둡게 둔다** — 영상 위에 얹히는 물건이라 화면이 밝든 어둡든 검은 박스에 흰
글자가 가장 안전하다.

네 값을 바꿀 수 있다 — 글자 크기 · 글자 색 · 배경 색 · 배경 투명도
(`references/api.md#화면-자막`). 몇 가지 조합:

| 쓰임 | 설정 |
|---|---|
| 기본 (영상 자막) | 그대로 |
| 배경 없이 글자만 | `opacity: 0` — 배경이 단순하고 어두울 때 |
| 옅게 깔기 | `opacity: 0.25` — 배경은 흐리게, 글자는 또렷하게 |
| 브랜드 색 | `bg: "#2b0b1f", color: "#ffe066"` |
| 쇼츠 (크게) | `size: 56, opacity: 0.85` — 작은 화면에서 확실히 읽히게 |

**배경 투명도를 낮춰도 글자는 안 흐려진다.** 배경이 글자 뒤에 깔린 별도 레이어라서다.

**자막과 로어서드(`lower`)를 같이 쓰지 않는다.** 둘 다 화면 아래를 쓴다.
`lower` 를 쓰는 비트에서는 자막을 끄거나(`S`), 로어서드를 다른 비트로 옮긴다.

## 모션 톤 (`motion`)

등장·전환의 이징과 시간을 한 세트로 고른다. 기본은 `apple`.

```bash
node <skill>/assets/sv.js deck.json out.html --motion apple   # 기본
node <skill>/assets/sv.js deck.json out.html --motion plain
```
`spec.motion` · `toHTML(spec, { motion: 'plain' })` 도 같다.

| | `apple` (기본) | `plain` |
|---|---|---|
| 주 커브 | `cubic-bezier(.32,.72,0,1)` | `cubic-bezier(.2,.85,.25,1)` |
| 요소 등장 | .74s (불투명도는 .42s) | .46s |
| 씬 전환 | .68s | .52s |
| 올라오는 거리 | 16px | 26px |
| 시작 배율 | 0.965 → 1 | 없음 |
| 글자 스태거 | 52ms | 70ms |

**`apple` 이 "쫀득한" 이유는 오버슈트가 아니다.** 셋이 겹쳐서 나온다:

1. **긴 꼬리 감속** — `.32,.72,0,1` 은 진행률 81% 를 지나서도 남은 거리를 계속 다듬는다.
   빠르게 나타난 뒤 마지막을 눌러 붙이는 그 느낌이 여기서 온다.
2. **불투명도가 먼저 끝난다** — 색은 .42s 에 다 차고, 위치·크기는 .74s 까지 자리를 찾아간다.
   "먼저 나타나고 그다음 앉는다."
3. **이동은 줄이고 배율을 얹는다** — 26px → 16px 로 줄이고 대신 0.965 → 1 로 다가오게 한다.
   멀리 움직이는 것보다 이게 더 묵직하다.

> 오버슈트(튀는 것)는 **픽토그램 한 칸처럼 작은 것에만** 준다(`--ez-pop`).
> 16px 이동에 오버슈트를 걸면 0.1px 밖에 안 넘어가 체감이 없고, 이동을 키워서
> 튀게 하면 화면이 산만해진다.

값은 전부 CSS 변수로 나가므로 `spec.css` 로 하나씩 덮어쓸 수 있다:

```jsonc
{ "css": ":root{--d-rv:.9s;--rise:22px}" }
```
